<task type="auto">
  <name>Task 1: Implement segment body DCE for unused declarations and if(false)</name>
  <files>crates/qwik-optimizer-oxc/src/transform.rs</files>
  <action>
SWC applies unused-declaration stripping to segment bodies via its `MinifyMode::Simplify` pass. OXC serializes segment body code as strings during traversal, so DCE must be applied as post-processing on the body code string.

**Approach: Parse-transform-reserialize the body code.**

Create a new function `apply_segment_body_dce(body_code: &str) -> String` that:

1. Wraps the body code in a parseable context: `var __body__ = <body_code>` (the body is an arrow/function expression)
2. Parses with OXC parser
3. Applies two DCE passes on the arrow/function body statements:

**Pass A: Strip unused declarations.**
For each statement in the function body:
- `const x = expr;` / `let x = expr;` -- if `x` is not referenced anywhere else in the body, remove the entire statement (if the init has no side effects) or convert to expression statement (if init may have side effects). For simplicity, remove only when init is a literal, identifier, or simple expression. Keep when init is a call expression (may have side effects).
- `function f() {}` -- if `f` is not referenced in the body, remove entirely (function declarations are never side-effectful).
- `class C {}` -- if `C` is not referenced in the body, remove entirely (class declarations without decorators are not side-effectful).
- Destructured const: `const {a, b} = expr;` -- if NONE of a, b are referenced, treat same as above.
- `try/catch` with no side effects in try block -- SWC removes these too. Check example_9.

To determine if a name is referenced: scan all IdentifierReference nodes in the body (excluding the declaration itself). Build a reference set, then check membership.

**Pass B: Eliminate if(false) branches.**
For each `if` statement: if the test is a `BooleanLiteral(false)` or `!true`:
- If no else branch: remove the statement entirely
- If else branch exists: replace with else branch contents

This reuses the same logic as `eliminate_dead_if_statements` in `const_replace.rs`. You can call that function directly on the parsed body statements, or inline the logic.

4. Reserialize the modified arrow/function body back to a string using OXC codegen.
5. Return the new body code string.

**Where to call this:** In `exit_program` or wherever segment_body_codes are finalized, iterate over `self.segment_body_codes` and apply DCE to each body code string:

```rust
for (_, body_code) in self.segment_body_codes.iter_mut() {
    *body_code = apply_segment_body_dce(body_code);
}
```

The timing matters: this must happen AFTER body codes are captured but BEFORE they're used for segment module generation.

**IMPORTANT performance note:** Only apply DCE if the body code is non-trivial (e.g., contains `const` or `let` or `function` or `class` or `if`). Skip for simple expression bodies.

**IMPORTANT:** Do NOT modify the golden .snap files. Only generate .snap.new for comparison.

<task type="auto">
  <name>Task 2: Remove invalid_decl_stack function/class declarations from component body</name>
  <files>crates/qwik-optimizer-oxc/src/transform.rs</files>
  <action>
Fix example_capturing_fn_class: function/class declarations tracked in `invalid_decl_stack` (which get C02 diagnostics) should be REMOVED from the component body output, not just excluded from captures.

SWC removes these declarations during its transform. In OXC, the declarations remain in the component body code because nothing strips them.

**Approach:** In exit_call_expression for component$ (around the section that handles props destructuring and capture reclassification), after collecting the `parent_invalid_decls`:

1. The `parent_invalid_decls` HashSet contains names of function/class declarations that were classified as invalid (fn/class inside $() scope).
2. For the component's body code (in `segment_body_codes`), apply a post-processing step that removes statement-level function/class declarations whose name is in the invalid set.

Specifically, after body code is serialized but before it's stored, parse the body code, remove matching function/class declarations, and reserialize.

Alternatively, if Task 1's `apply_segment_body_dce` is already implemented, extend it to accept an optional set of names to forcibly remove (even if they ARE referenced -- because C02 means they shouldn't be captured and their declarations should be removed).

**Note:** The invalid declarations are in the PARENT component's body, not in the nested segment's body. So the removal needs to happen on the component segment's body code, not the nested segment's body code.

Look for the component segment in `segment_body_codes` (keyed by the component$ call's span.start) and remove function/class declarations matching `parent_invalid_decls`.
