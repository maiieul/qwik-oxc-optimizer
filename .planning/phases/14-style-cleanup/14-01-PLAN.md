  <action>
Read each file fully. Remove comments that match these patterns (the code already says what these comments restate):

1. **Numbered step comments** like `// 1. Create the arena allocator for this module` before a line that creates an allocator. These add no value when the code is self-documenting. Remove the numbers and the comment unless the comment explains *why* something is done in a particular order. In lib.rs, the pipeline steps (1-9) should lose their numbers but keep meaningful WHY comments (e.g., "This must happen before traverse_mut so that..." is useful; "// 1. Build replacement map" before `build_replacement_map()` is not).

2. **"Check if X" / "Skip if X" comments** before the corresponding `if` or `continue`. Examples: `// Skip if already processed` before `if seen.contains(name) { continue; }`, `// Check if this segment should be stripped` before `if self.should_strip_ctx_name(name)`. Remove these.

3. **"Get the X" / "Build the X" comments** before a call to a function with that exact name. Examples: `// Build the replacement expression` before `build_replacement(...)`. Remove these.

4. **Inline obvious explanations** like `// Not a global, not an import, not body-local, not module-level -> it's a capture` before `captures.push(name)`. The function is called `compute_captures`; the else branch is obviously a capture. Remove.

5. **Test comments** in lib.rs test functions like `// Should have at least 1 module`, `// The main module code should contain qrl()` -- these are noise because the assertion below already makes the expectation clear. Remove all such comments from `#[cfg(test)]` blocks.

**KEEP these comment types:**
- Module-level `//!` doc comments (file purpose)
- `///` doc comments on public/private structs, enums, and functions
- Comments explaining non-obvious *why* (e.g., "OXC Scoping is consumed by traverse_mut", "This must happen before X because Y")
- Comments about known deviations or workarounds
- Separator comments like `// ---------------------------------------------------------------------------`

After removing, run `cargo build` to confirm the crate compiles.
