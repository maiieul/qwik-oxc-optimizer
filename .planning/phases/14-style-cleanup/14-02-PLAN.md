  <action>
Read each file fully. Apply these formatting normalizations:

**1. Match arm cleanup:**

- In `const_replace.rs`: The `replace_identifiers_in_expression` function has match arms for every `Expression` variant. Many arms simply recurse into sub-expressions. Look for match arms that are dead code or unreachable given the function's input constraints. For arms that are genuinely needed but have identical recursive patterns, consider whether a wildcard `_` arm can replace multiple no-op arms. However, be CONSERVATIVE -- only collapse arms where the pattern is `SomeVariant(..) => { /* recurse into sub-exprs */ }` and the recursion does nothing useful (e.g., matching a literal variant and doing nothing).

- In `transform.rs`: The `is_const_expression` function and `detect_signal_wrap` function have match arms. Verify no unreachable arms exist. Clean up any `_ => false` or `_ => None` arms that are preceded by arms covering all realistic cases -- these are fine to keep for exhaustiveness but should not have misleading comments.

- In `collector.rs`: The `walk_statement` and `walk_expression_for_calls` functions have large match blocks. Look for arms that simply recurse without doing anything useful -- e.g., `Statement::LabeledStatement(labeled) => { walk_statement(ctx, &labeled.body); }` that would never contain dollar calls. These are NOT dead code (they could theoretically contain $-calls), so keep them, but clean up formatting (consistent brace style, consistent spacing).

**2. Formatting consistency across files:**

- **Trailing commas in struct initialization:** Some files use trailing commas in struct init, some don't. Standardize: always include trailing commas in multi-line struct init (Rust convention).

- **Blank lines between functions:** Ensure exactly one blank line between function definitions (no double blanks, no missing blanks).

- **Consistent `use` import grouping:** Each file should have: (1) std imports, (2) external crate imports (oxc::*), (3) crate-local imports (crate::*). Separate groups with one blank line. Currently some files mix these.

- **Consistent match arm formatting:** Single-expression arms on one line (`Variant => expr,`). Multi-statement arms in braces with each statement on its own line. No mixing of styles within a single match block.

Run `cargo build` after each file to catch formatting issues early. Run `cargo test` after all 4 files are done.
