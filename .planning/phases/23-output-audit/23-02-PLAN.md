**Classification criteria (from user decisions -- these are locked):**

Runtime-breaking:
- Missing captures: runtime-breaking IF the variable is actually referenced in the segment body (the capture is needed for the code to execute)
- QRL wrapping differences (wrong wrapper function): always runtime-breaking
- Import path differences (wrong path, missing re-export): always runtime-breaking
- Syntax differences (const vs let, structural differences): runtime-breaking -- these affect program semantics
- Missing/extra segments (module count mismatch): missing segments = runtime-breaking (lazy loading breaks); extra segments = investigate per case

Cosmetic:
- Extra parens, reordering that doesn't change semantics: cosmetic unless syntactically wrong
- Extra captures (unnecessary closure variables): generally cosmetic -- track but don't classify as runtime-breaking
- Whitespace/formatting: already normalized out by Plan 01

**Category assignment:** Each deviation gets one of:
- `capture` -- capture analysis differences (missing/extra captures, capture variable lists)
- `import` -- import path or import statement differences
- `qrl` -- QRL wrapping differences (wrong wrapper function, wrong arguments)
- `codegen` -- code generation differences (const/let, structural code differences, expression formatting)
- `module` -- module count or module matching differences (extra/missing modules)

**Think like a JS engine** (per user guidance): For each deviation, ask "would a JavaScript runtime produce different behavior?" If yes, it's runtime-breaking. If the code would execute identically, it's cosmetic.

**Detail level** is at Claude's discretion (per user decision). Balance compact tables with enough diff context to understand each deviation. For large groups of similar deviations (e.g., all JSX event handler capture differences), group them with a single explanation rather than repeating the same rationale for each.

**Important:** This report must be clear enough for the user to approve or reject classifications. The user didn't write the original optimizer, so explain WHY each classification was made in terms a non-expert can evaluate.
