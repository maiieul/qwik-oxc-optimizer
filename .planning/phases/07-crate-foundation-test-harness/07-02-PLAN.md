Create `tests/spec_parser.rs` as a module that parses spec markdown files into structured data. The architecture blueprint Section 4 has the design, but the actual spec format has nuances that must be handled.

Define these types:

```rust
pub struct SpecFile {
    pub name: String,
    pub config_overrides: Vec<(String, String)>,  // preserve order
    pub input_code: String,
    pub input_filename: String,  // default "test.tsx"
    pub expected_modules: Vec<ExpectedModule>,
    pub expected_diagnostics: Vec<serde_json::Value>,
    // For relative_paths special case:
    pub additional_inputs: Vec<(String, String)>,  // (path, code) for multi-input tests
}

pub struct ExpectedModule {
    pub path: String,
    pub is_entry: bool,
    pub code: String,
    pub segment: Option<serde_json::Value>,
}
```

Implement `pub fn parse_spec_file(path: &Path) -> Result<SpecFile, String>` with this logic:

1. **Extract test name** from `# Test: {name}` on line 1.

2. **Parse configuration table** from `## Test Configuration` section. The table has `| Option | Value |` format. Skip lines with `*(all defaults)*`. Extract key-value pairs. Known keys:
   - `Entry Strategy` -> entry_strategy
   - `Mode` -> mode
   - `Transpile TS` -> transpile_ts
   - `Transpile JSX` -> transpile_jsx
   - `Explicit Extensions` -> explicit_extensions
   - `Preserve Filenames` -> preserve_filenames
   - `Minify` -> minify
   - `Source Maps` -> source_maps
   - `Src Dir` -> src_dir
   - `Root Dir` -> root_dir
   - `Scope` -> scope
   - `Core Module` -> core_module
   - `Is Server` -> is_server
   - `Strip Exports` -> strip_exports
   - `Strip Ctx Name` -> strip_ctx_name
   - `Strip Event Handlers` -> strip_event_handlers
   - `Reg Ctx Name` -> reg_ctx_name

3. **Extract input source code** from the code block under `### Source Code`. The code block starts with ````tsx` or ````typescript` or ````javascript` and ends with the next `````.

   Special case: `relative_paths.md` has `### Source Code: lib.mjs (dependency module)` and `### Source Code: main.tsx (main component)` -- TWO input code sections. Handle this by checking for `### Source Code:` prefix and extracting the filename from the heading. The first is an additional input, the second is the primary input (or treat based on the heading text).

4. **Extract output modules** from `### Module: {path}` or `### Module: {path} (ENTRY POINT)` sections:
   - `is_entry` = true if "(ENTRY POINT)" is present
   - Extract the code block immediately following the heading (skip the `<details>` AST block)
   - Look for `#### Segment Metadata` after the module code. If present, extract the JSON code block as `serde_json::Value`.

5. **Extract diagnostics** from `## Diagnostics` section. Parse the JSON code block as `Vec<serde_json::Value>`. If absent or empty `[]`, use empty vec.

**Parsing strategy:** Use line-by-line scanning (not regex). Track current section via heading detection. Code blocks are delimited by triple-backtick lines.

**Edge cases to handle:**
- Spec files with `<details>` blocks between the module code and the next section -- skip these entirely (they contain AST JSON we don't need).
- Code blocks with language specifiers (`tsx`, `json`, `javascript`) -- strip these from the delimiter.
- The `relative_paths.md` file has a `**Note:**` paragraph before the config table.
- Some spec files may have empty diagnostics section (just `[]`).
- Some `#### Segment Metadata` sections are absent for non-entry-point modules -- `segment` should be `None`.

Also implement `pub fn build_options(spec: &SpecFile) -> TransformModulesOptions` that creates a `TransformModulesOptions` from a parsed spec, applying config overrides. Use the crate's types directly (`use qwik_optimizer_oxc::*`). Map string config values to enum variants:
- "Inline" -> `EntryStrategy::Inline`
- "Segment" -> `EntryStrategy::Segment`
- "Hoist" -> `EntryStrategy::Hoist`
- etc.
- "Dev" -> `EmitMode::Dev`, "Prod" -> `EmitMode::Prod`, "Lib" -> `EmitMode::Lib`
- "Simplify" -> `MinifyMode::Simplify`, "None" -> `MinifyMode::None`
- "true"/"false" -> bool

Also implement `pub fn spec_dir() -> PathBuf` that resolves to `.planning/spec/` from the workspace root:

```rust
mod spec_parser;

#[cfg(test)]
mod tests {
    use super::spec_parser;

    /// Verify that all 162 spec files parse without errors.
    /// This test does NOT run the optimizer -- it only validates
    /// that the spec parser can extract input, output, and metadata
    /// from every spec markdown file.
    #[test]
    fn test_parse_all_specs() {
        let specs = spec_parser::load_all_specs();

        // Must find all 162 specs
        assert!(
            specs.len() >= 162,
            "Expected at least 162 spec files, found {}",
            specs.len()
        );

        let mut failures = Vec::new();

        for spec in &specs {
            // Every spec must have input code (except relative_paths which has additional_inputs)
            if spec.input_code.is_empty() && spec.additional_inputs.is_empty() {
                failures.push(format!("{}: no input code found", spec.name));
                continue;
            }

            // Every spec must have at least one output module
            if spec.expected_modules.is_empty() {
                failures.push(format!("{}: no output modules found", spec.name));
                continue;
            }

            // Every output module must have non-empty code
            for module in &spec.expected_modules {
                if module.code.is_empty() {
                    failures.push(format!(
                        "{}: empty code in output module '{}'",
                        spec.name, module.path
                    ));
                }
            }

            // Entry point modules must have segment metadata
            for module in &spec.expected_modules {
                if module.is_entry && module.segment.is_none() {
                    failures.push(format!(
                        "{}: entry point module '{}' missing segment metadata",
                        spec.name, module.path
                    ));
                }
            }
        }

        if !failures.is_empty() {
            panic!(
                "Spec parse failures ({}/{}):\n{}",
                failures.len(),
                specs.len(),
                failures.join("\n")
            );
        }

        // Print summary
        let total_modules: usize = specs.iter().map(|s| s.expected_modules.len()).sum();
        let entry_modules: usize = specs.iter()
            .flat_map(|s| &s.expected_modules)
            .filter(|m| m.is_entry)
            .count();
        let with_config: usize = specs.iter()
            .filter(|s| !s.config_overrides.is_empty())
            .count();

        eprintln!(
            "Parsed {} specs: {} output modules ({} entry points), {} with config overrides",
            specs.len(), total_modules, entry_modules, with_config
        );
    }

    /// Verify that build_options produces valid TransformModulesOptions
    /// for a selection of representative specs.
    #[test]
    fn test_build_options() {
        let specs = spec_parser::load_all_specs();

        for spec in &specs {
            let options = spec_parser::build_options(spec);

            // Options must have at least one input
            assert!(
                !options.input.is_empty(),
                "{}: build_options produced empty input",
                spec.name
            );

            // Input code must match spec
            if !spec.input_code.is_empty() {
                assert_eq!(
                    options.input.last().unwrap().code,
                    spec.input_code,
                    "{}: input code mismatch",
                    spec.name
                );
            }

            // Verify JSON serialization works
            let json = serde_json::to_string(&options);
            assert!(
                json.is_ok(),
                "{}: failed to serialize options: {:?}",
                spec.name,
                json.err()
            );
        }
    }

    /// Stub test for future: run optimizer on all specs.
    /// Currently just verifies the stub returns empty output.
    #[test]
    fn test_transform_stub() {
        use qwik_optimizer_oxc::transform_modules;

        let specs = spec_parser::load_all_specs();
        let spec = &specs[0]; // Just test one for now
        let options = spec_parser::build_options(spec);

        let result = transform_modules(options);
        assert!(result.is_ok(), "transform_modules stub should not fail");

        let output = result.unwrap();
        // Stub returns empty -- this will change in Phase 8
        assert!(output.modules.is_empty(), "stub should return empty modules");
        assert!(output.diagnostics.is_empty(), "stub should return no diagnostics");
    }
}
```
