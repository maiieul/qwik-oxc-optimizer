**Step 2: Fix QRL extraction for JSX event handlers**

The audit shows 45 specs where event handlers like `onClick$={() => ...}` remain inline instead of being extracted to lazy segments. The issue is likely in the interplay between:

1. `create_jsx_event_segments_recursive()` in transform.rs -- this creates the segment record but may not be correctly serializing the body code into `segment_body_codes`
2. The body serialization path in the Traverse exit handlers -- when a JSX attribute value is a lambda, the body code needs to be captured as a string for the segment module
3. `get_jsx_lambda_span()` in jsx_transform.rs -- this identifies the span of the lambda in a JSX attribute value, but may fail for certain patterns (arrow functions with TypeScript annotations, parenthesized expressions, etc.)

For each of these, trace the code path for a known failing spec (e.g., `destructure_args_inline_cmp_block_stmt`) and compare to a passing spec. The key question is: after `create_jsx_event_segments_recursive()` creates a SegmentData, is the body code being captured in `segment_body_codes` for that segment's span?

Look at how `exit_expression` handles $-calls -- it serializes body code via OXC codegen on the CallExpression's argument (the lambda). For JSX event handlers, the body serialization may happen through a different path (or not at all). If JSX event segments don't go through the same body serialization path as regular $-calls, that explains both the empty-segment (segment exists but no body) and qrl-extraction (segment not properly generated) deviations.

The fix is to ensure JSX event handler lambdas are serialized to `segment_body_codes` the same way explicit $-call arguments are. This likely requires:
- Capturing the lambda expression span from JSX attributes
- Running OXC codegen on that span to produce the body string
- Storing it in `segment_body_codes` keyed by the segment's span.start

**Step 3: Fix empty segment bodies**

32 deviations show segments that exist but have empty bodies. This is directly caused by the body serialization issue above. After fixing the JSX event handler body serialization, verify that:
- `body_codes` in lib.rs line ~217 finds a matching entry for every non-stripped segment
- The `unwrap_or("")` fallback is only hit for legitimately empty segments (should be zero for non-stripped segments)

Add a diagnostic/warning when a non-stripped segment has no body code, to catch this class of bug in the future.

After fixes, run `cargo test --package qwik-optimizer-oxc` to ensure existing tests still pass.
