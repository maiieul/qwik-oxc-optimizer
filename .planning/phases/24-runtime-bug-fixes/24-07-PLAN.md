Three fixes in collector.rs:

**Fix 1: AssignmentPattern in `collect_binding_pattern_names_into()` (line ~336)**

The current function matches on `BindingIdentifier`, `ObjectPattern`, and `ArrayPattern` but NOT `AssignmentPattern`. In OXC's AST, destructuring defaults like `I5=v2` or `d=v2` create a BindingPattern with kind `AssignmentPattern` containing `left: BindingPattern` (the actual identifier) and `right: Expression` (the default value).

Add the AssignmentPattern case to recursively process the left side:

```rust
// In the match on BindingPatternKind:
BindingPatternKind::AssignmentPattern(assign) => {
    collect_binding_pattern_names_into(names, &assign.left);
}
```

This will handle patterns like:
- `const [a, {b, v1: [c], d=v2, ...e}, f=v3, ...g] = obj` → now collects `d` and `f`
- `const [I2, {I3, v1: [I4], I5=v2, ...I6}, I7=v3, ...I8] = obj` → now collects `I5` and `I7`

Note: Check how the pattern matching works in this code. If the function matches on `BindingPattern` (the struct) directly via some deref/match mechanism, check the OXC API. The key is that `AssignmentPattern` must be handled wherever `BindingPatternKind` variants are dispatched.

**Fix 2: TSEnumDeclaration in `collect_declaration_names()` (line ~313)**

Add handling for TypeScript enum declarations:

```rust
Declaration::TSEnumDeclaration(enum_decl) => {
    names.insert(enum_decl.id.name.as_str().to_string());
}
```

This will fix `export enum Thing { A, B }` → `Thing` added to `module_level_decls`.

Note: TS enum's `id` field is a `BindingIdentifier`, not `Option<BindingIdentifier>`, so no `if let Some(...)` needed — just access `.id` directly. Verify this by checking the OXC AST definition for `TSEnumDeclaration`.

**Fix 3: Named default exports in `collect_default_export()` (line ~573)**

Currently `collect_default_export()` adds to `module_exports` but NOT to `module_level_decls`. For named default exports like `export default function DefaultFn() {}`, the name `DefaultFn` must be in `module_level_decls` so that `reclassify_module_level_decl_captures()` can generate a self-import for it.

Update `collect_default_export()` to also call `collect_declaration_names()` on the declaration when it's a function or class:

```rust
fn collect_default_export(ctx: &mut CollectContext, export: &ExportDefaultDeclaration<'_>) {
    ctx.module_exports.push(ExportInfo {
        name: "default".to_string(),
        is_reexport: false,
        span: (export.span.start, export.span.end),
    });

    match &export.declaration {
        ExportDefaultDeclarationKind::FunctionDeclaration(fn_decl) => {
            if let Some(ident) = &fn_decl.id {
                ctx.module_level_decls.insert(ident.name.as_str().to_string());
            }
        }
        ExportDefaultDeclarationKind::ClassDeclaration(class_decl) => {
            if let Some(ident) = &class_decl.id {
                ctx.module_level_decls.insert(ident.name.as_str().to_string());
            }
        }
        _ => {
            if let Some(expr) = export.declaration.as_expression() {
                ctx.current_var_name = Some("default".to_string());
                walk_expression_for_calls(ctx, expr);
                ctx.current_var_name = None;
            }
        }
    }
}
```
