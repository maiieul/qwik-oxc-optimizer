  <action>
Fix the import resolution pipeline so extracted segments have all required imports. The issue manifests as three audit patterns: missing-imports (39), codegen-missing-imports (24), and import-mismatch (13).

**Step 1: Understand the current import tracking flow**

When a $-call body is extracted as a segment, the capture analysis in collector.rs classifies each outer reference as:
- LocalCapture: a variable from the enclosing scope that must be serialized via _captures
- ImportReemit: an import binding that should be re-emitted as an import in the segment module
- Skipped: a known global or framework import

The reemitted_imports from CaptureAnalysisResult should be propagated to SegmentData.needed_imports, which code_move.rs uses to emit import statements in the segment.

**Step 2: Diagnose why imports are missing**

Read a specific failing spec, e.g., `example_11` where expected imports include `dep3`, `Header`, `bbar`, and `qrl` but actual only has `qrl`. Trace:

1. Does collector.rs `compute_captures()` see the references to `dep3`, `Header`, `bbar` in the $-call body?
2. Are they classified as ImportReemit (correct) or LocalCapture (wrong) or skipped (wrong)?
3. Does `needed_imports` in SegmentData get populated from `reemitted_imports`?
4. Does code_move.rs `build_segment_code_with_hoisted()` emit the needed_imports as import statements?

Check if code_move.rs currently only emits framework imports (like `_captures`, `qrl`, `_jsxSorted`) from body_code string scanning, but does NOT emit user-code imports (like `dep3`, `Header`) from the `needed_imports` field. If so, add logic to emit needed_imports as import statements.

**Step 3: Fix the pipeline**

The fix likely involves:

1. In collector.rs `compute_captures()`: Ensure non-core imports (user imports like `dep3 from "dep3/something"`) are correctly classified as ImportReemit rather than LocalCapture when they appear in a $-body.

2. In transform.rs exit_expression (where captures are computed): Ensure `reemitted_imports` from CaptureAnalysisResult is stored in `seg.needed_imports`.

3. In code_move.rs `build_segment_code_with_hoisted()`: After the framework import emission, iterate over `segment.needed_imports` and emit each one:
   - Default imports: `import NAME from "SOURCE";`
   - Named imports: `import { NAME } from "SOURCE";`
   - Namespace imports: `import * as NAME from "SOURCE";`

The import information is available from CaptureAnalysisResult.reemitted_imports which stores (local_name, source, is_default). This may need enrichment to distinguish namespace imports (`import * as X`) from named imports (`import { X }`).

4. Handle the import-mismatch pattern where some imports are missing AND others are extra. The extra imports may come from incorrect body_code string scanning. Verify that framework import detection in code_move.rs (e.g., `body_code.contains("_jsxSorted")`) doesn't produce false positives.

After fixes, run `cargo test --package qwik-optimizer-oxc` to ensure no regressions.
