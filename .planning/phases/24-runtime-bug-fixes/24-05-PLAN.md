  <action>
In `compute_captures()` (collector.rs, around line 192-194), remove the block that skips `module_level_decls`:

```rust
// REMOVE THIS BLOCK:
if collect_result.module_level_decls.contains(name) {
    continue;
}
```

**Why this is the correct fix:** Module-level declarations (`const foo = ...`, `function Header() {}`, `class bar {}`) are declared at the top level of the source module. When a *nested* `$()-body` references them, the body gets extracted into a separate segment module that has NO access to the parent module's top-level scope. The SWC optimizer treats these as captures -- the parent module serializes them via `_captures[]` and the segment module restores them via `const foo = _captures[N]`.

The current code skips these entirely, meaning the segment body references the symbol but it's neither captured nor imported -- a runtime crash (`ReferenceError: foo is not defined`).

**Why this doesn't break top-level segments:** Top-level `$()-calls` (where `capture_stack` is empty after popping) already have their captures zeroed out in transform.rs (lines 1293-1296):
```rust
if is_top_level_dollar_call {
    seg.captures = false;
    seg.capture_names = vec![];
}
```
So even though `compute_captures()` would now return module-level decls as captures, they get cleared for top-level segments.

**Edge case -- module_level_decls that are also exported:** If the source has `export const Header = component$(...)` and a nested `$()-body` references `Header`, it should still be captured. The SWC optimizer captures exported module-level declarations the same as non-exported ones.

After removing the skip, `compute_captures()` will classify module-level declarations as `LocalCapture` (added to `capture_names`) since they're not in `body_local_decls`, not globals, not dollar imports, and not in `module_imports`. This is exactly what the SWC optimizer does.

Also update the test `test_compute_captures_import_not_captured` if it references module-level decls indirectly, and add a new test:

```rust
#[test]
fn test_compute_captures_module_level_decl_captured() {
    // Module-level declarations should be captured (not skipped)
    // when referenced in a $()-body. The segment module can't access
    // the parent module's top-level scope.
    let collect_result = parse_and_collect(
        r#"import { $, component$ } from '@qwik.dev/core';
const foo = 1;
function Header() {}
export const App = component$(() => {
    return $(() => foo + Header);
});"#,
    );

    // Simulating the inner $() body referencing module-level decls
    let body_ident_refs = vec!["foo".to_string(), "Header".to_string()];
    let body_local_decls: HashSet<String> = HashSet::new();

    let result = compute_captures(&body_ident_refs, &body_local_decls, &collect_result);
    // foo and Header are module-level decls, but should be captured
    // for nested segments (the segment can't access parent module scope)
    assert_eq!(
        result.capture_names,
        vec!["foo".to_string(), "Header".to_string()],
        "Module-level declarations should be captured, not skipped"
    );
    assert!(result.reemitted_imports.is_empty());
}
```

**Part A: Review and adjust transform.rs capture filtering**

After removing the `module_level_decls` skip from `compute_captures()`, the capture analysis will now return module-level declarations as captures for ALL segments (top-level and nested). Verify that the existing code already handles this correctly:

1. **Top-level $-calls (lines 1293-1296):** These already zero out captures (`seg.captures = false; seg.capture_names = vec![];`). No change needed -- module-level decls won't leak into top-level segment captures.

2. **Nested $-calls (lines 1297-1300):** These use `capture_result.capture_names` directly. Module-level decls will now correctly appear here. No change needed.

3. **JSX event handler captures (around line 651):** When inside a `$()-body` (capture_stack non-empty), captures are filtered to only include names in `all_parent_decls` (the merged capture_stack frames). Module-level declarations like `Header`, `foo` etc. will NOT be in the capture_stack -- they're module-level, not declared inside any `$()-body`.

This is the critical issue. The JSX event handler filter at line 658-661:
```rust
.filter(|name| all_parent_decls.contains(name))
```
will REMOVE module-level declarations from captures because they're not in any capture_stack frame.

**Fix:** When filtering JSX event handler captures against parent scopes, also include `module_level_decls` as valid capture sources. Update the filter logic:

```rust
let capture_result = if !self.capture_stack.is_empty() {
    let all_parent_decls: HashSet<String> = self
        .capture_stack
        .iter()
        .flat_map(|(_, decls)| decls.iter().cloned())
        .collect();
    let filtered_names: Vec<String> = capture_result
        .capture_names
        .into_iter()
        .filter(|name| {
            all_parent_decls.contains(name)
                || self.collected.module_level_decls.contains(name)
        })
        .collect();
    collector::CaptureAnalysisResult {
        capture_names: filtered_names,
        reemitted_imports: capture_result.reemitted_imports,
        diagnostics: capture_result.diagnostics,
    }
} else {
    capture_result
};
```

**Why:** Module-level declarations ARE valid captures for JSX event handlers inside component bodies. The handler will be extracted into its own segment module, which can't access the parent module's top-level scope. The SWC optimizer captures these.
