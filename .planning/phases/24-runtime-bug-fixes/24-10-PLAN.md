  <name>Task 1: Fix derive_display_name to use parent_display_name for nested $() calls</name>

  <action>
The `derive_display_name()` function (around line 1058) currently builds display names from `ctx.current_var_name`, `callee_suffix`, and `ctx.scope_prefix` — but completely ignores `ctx.parent_display_name`. This causes nested `$()` calls to collide when they share the same base variable name.

**SWC behavior (from spec example_1):**
- Outer `$(() => { return <div onClick={$(...)}/>; })` assigned to `renderHeader` → display name: `renderHeader`
- Inner `$((ctx) => console.log(ctx))` inside JSX onClick → display name: `renderHeader_div_onClick`
- `component($(() => { console.log("mount"); return render; }))` assigned to `renderHeader` → display name: `renderHeader_component`

The SWC optimizer appends the wrapper function context (`_component` from `component$()`) to the display name. The JSX element path (`_div_onClick`) is already handled by `derive_jsx_event_display_name()`.

**The fix:**
When `ctx.parent_display_name` is Some, the nested `$()` call's display name should incorporate the parent context. Specifically:

1. For `$()` calls that are arguments to wrapper functions like `component$()`, the display name should be `{varName}_{wrapperCalleeSuffix}`. Example: `renderHeader_component` (var=`renderHeader`, wrapper=`component`).

2. For bare `$()` calls nested inside a parent `$()` body (not through a wrapper function), they already get different display names through JSX event handling. But if they're non-JSX nested calls, they need parent context.

Look at how `walk_expression_for_calls()` (around line 700) processes nested calls:
- Line ~707: calls `derive_display_name()` for the display name
- Line ~709: saves `parent_name = ctx.parent_display_name.clone()`
- Line ~720: sets `ctx.parent_display_name = Some(display_name)` for nested processing

The issue is that `derive_display_name()` doesn't incorporate `ctx.parent_display_name` in its output. But we need to be careful — for top-level `$()` calls, `parent_display_name` is None. For wrapper functions like `component$()`, the callee_suffix already provides uniqueness via `{varName}_{calleeSuffix}`.

**The real collision case:** When a variable like `renderHeader` has BOTH a direct `$()` assignment AND a `component($())` assignment, both calls have `current_var_name = "renderHeader"`:
- Direct `$()`: callee is `$`, suffix is empty → display name = `renderHeader`
- `component($())`: the outer `component()` call sets var_name, then the inner `$()` call also has var_name = `renderHeader` and callee suffix empty → display name = `renderHeader` (COLLISION!)

The SWC optimizer distinguishes these by including the wrapper function name in the display path. When `$()` is the direct argument of another call (like `component($())`), the wrapper function name should be appended.

**Implementation approach:**
Check if `parent_display_name` is already set when `derive_display_name` is called. If so, the current `$()` is nested. Incorporate the parent into the name:

```rust
fn derive_display_name(ctx: &CollectContext, callee_name: &str) -> String {
    let var_name = ctx.current_var_name.as_deref().unwrap_or("");
    let callee_suffix = callee_name.strip_suffix('$').unwrap_or("");

    let base = if var_name.is_empty() {
        if callee_suffix.is_empty() {
            "s_".to_string()
        } else {
            callee_suffix.to_string()
        }
    } else if callee_suffix.is_empty() {
        var_name.to_string()
    } else {
        format!("{var_name}_{callee_suffix}")
    };

    // For nested $() calls, prepend the parent display name context.
    // This distinguishes e.g. renderHeader (from $()) from renderHeader_component (from component$($()))
    if let Some(ref parent) = ctx.parent_display_name {
        // Already nested — include parent context
        // But avoid double-prepending if base already starts with parent
        if !base.starts_with(parent.as_str()) {
            return format!("{parent}_{base}");
        }
    }

    // Prepend scope prefix (from enclosing function declarations)
    if let Some(ref prefix) = ctx.scope_prefix {
        format!("{prefix}_{base}")
    } else {
        base
    }
}
```

**BUT WAIT** — this needs more careful analysis. Read the code flow carefully:

In `walk_expression_for_calls()`, when processing `component$($(() => {...}))`:
1. First the outer `component$()` call is detected (callee = `component$`)
2. `derive_display_name()` is called → `renderHeader_component` (var=renderHeader, suffix=component)
3. `parent_display_name` is set to `renderHeader_component`
4. Then the INNER `$()` argument is recursively walked
5. But the inner `$()` has callee = `$`, and the display name would be recalculated...

Actually, read the walk_expression_for_calls code more carefully. When a `$()` call is found:
- The display name is derived
- A DollarCallSite is created
- The arguments are walked for NESTED dollar calls

The issue might be that when `component($(...))` is processed:
- `component$` is NOT a `$()` call itself (it's `component` + `$` as part of the name)
- OR `component$` IS detected as a dollar call

Check how the code distinguishes `$()` from `component$()` from `component($())`. The callee detection logic is crucial.

Read the callee detection code carefully, then implement the fix that makes display names unique. The key reference is the SWC expected output from the spec files.
