**hash.rs -- Implement segment hash computation:**

Port the exact algorithm validated in `poc/src/poc_03_multi_module.rs`:

1. `compute_segment_hash(scope: Option<&str>, rel_path: &str, display_name: &str) -> String`

   - If scope is Some, write scope bytes
   - Write rel_path bytes
   - Write display_name bytes
   - Call `hasher.finish()` to get u64
   - Encode with `base64::engine::general_purpose::URL_SAFE_NO_PAD.encode(hash.to_le_bytes())`
   - Replace '-' and '_' with '0' in the result
   - Return the 11-char string

**collector.rs -- Implement first-pass AST analysis:**

Replace the stub with a real implementation that walks the parsed AST to collect:

1. **Dollar imports from @qwik.dev/core**: Walk `program.body` and for each `ImportDeclaration` where source matches `@qwik.dev/core`:
   - Check each specifier. If it's an `ImportSpecifier` and the imported name is `$` or ends with `$`, add to `dollar_imports: HashSet<String>`.
   - Also record the full import info in `module_imports: Vec<ImportInfo>`.

2. **All module imports**: For every `ImportDeclaration`, record an `ImportInfo` with source, specifiers, is_qwik_core flag, and span.

3. **All module exports**: For every `ExportNamedDeclaration` and `ExportDefaultDeclaration`, record an `ExportInfo` with name, is_reexport flag, and span.

4. **Dollar call sites**: Walk the AST to find all `CallExpression` nodes where the callee is an `Identifier` matching a name in `dollar_imports`. For each found call site, construct a `DollarCallSite` with:
   - `callee_name`: the identifier name (e.g., "$", "component$")
   - `span`: (call.span.start, call.span.end)
   - `display_name`: derived from lexical context (see below)
   - `is_nested`: whether this call is inside another $-call body
   - `parent_name`: the parent $-call's display name if nested

**Display name derivation:** The display name follows the pattern `{filename}_{identifier}_{context}`:
   - For `export const Foo = component$(() => ...)`, display_name is `"Foo_component"` (variable name + callee without $)
   - For `const bar = $(() => ...)`, display_name is `"bar"` (variable name, bare $ has no suffix)
   - For nested `$` inside another `$` body, the display_name includes the parent context
   - The filename prefix is NOT included in display_name at this stage -- it's added later during segment data construction

**Implementation approach:** Since this is a read-only pass BEFORE traverse_mut, implement it as a simple recursive function walking `program.body` statements, not using `Traverse` trait:
   - Walk each statement in program.body
   - For ImportDeclaration: collect imports
   - For ExportNamedDeclaration/ExportDefaultDeclaration: collect exports
   - For variable declarations and other statements: recursively search for CallExpression nodes matching dollar_imports
   - Track nesting depth to detect nested dollar calls

Keep the function signature: `collect(program: &Program, scoping: &Scoping) -> CollectResult` -- but note that for Phase 8, we only need the import/export/call-site collection. The `scoping` parameter is passed through for future capture analysis (Phase 9). For now, it's unused in the collector but must be in the signature for API stability.

Add unit tests:
