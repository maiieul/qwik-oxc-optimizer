Fix entry module import scoping: stop emitting segment-only imports in the entry module, and fix the entry module body ordering to match SWC's assembly pattern.

Purpose: The core import scoping bug causes ALL import_tracker flags to emit imports into the entry module even when they are only used by segment bodies (which become separate files). This adds extra imports like `_jsxSorted`, `useStore`, `mongodb`, etc. to the entry module. SWC avoids this via DCE (dead code elimination). OXC needs a targeted unused-import scanner.
Output: Entry modules contain only imports that are actually referenced in the entry module code.
</objective>

  The entry module's `exit_program` method (line ~2489) currently emits ALL framework imports flagged by `import_tracker` regardless of whether they're actually used in the entry module body. This causes segment-only imports to leak into the entry module.

  **Strategy:** After building the new_stmts (synthetic imports) and before merging with old_body, scan the old_body statements to determine which identifiers are actually referenced. Then filter new_stmts to only include imports whose specifiers are referenced.

  **1. Build a helper function to collect referenced identifiers from statements:**

  Create a function (near `exit_program` or as a separate helper) that scans a list of statements and returns a `HashSet<String>` of all identifier names used:

  ```rust
  /// Collect all identifier names referenced in a list of statements.
  /// Skips import declarations themselves (we only want to see what the
  /// non-import code references).
  fn collect_referenced_identifiers(body: &[Statement<'_>]) -> HashSet<String> {
      let mut idents = HashSet::new();
      for stmt in body {
          // Skip import declarations -- we want to know what the CODE references
          if matches!(stmt, Statement::ImportDeclaration(_)) {
              continue;
          }
          collect_idents_from_stmt(stmt, &mut idents);
      }
      idents
  }
  ```

  The `collect_idents_from_stmt` function should recursively walk the statement collecting all `IdentifierReference` names. This can be done with a simple recursive walk, OR by serializing the statement to string and scanning for known identifiers (simpler but less precise).

  **Recommended approach (string scanning):** Since the entry module body is about to be codegen'd anyway, and we only need to check a known set of identifiers (the framework import specifier names), a simple string search is adequate:

  After building old_body (the non-import statements), serialize them to check which identifiers are present. However, since we're working at AST level in exit_program, we should do AST-level scanning.

  **Practical approach:** Instead of full AST walking, collect the set of identifiers we're about to import, then check each one against the old_body. Use OXC's visitor pattern or a simple recursive function.

  Actually, the simplest correct approach: build ALL new_stmts as before, then filter them. For each import statement in new_stmts, extract its specifier name(s), and check if that name appears in any non-import statement of old_body. If not, drop that import.

  **2. Modify exit_program to filter synthetic imports:**

  After the existing code that builds `new_stmts` (lines ~2494-2611) and before the body assembly (lines ~2654-2681), add filtering logic:

  ```rust
  // --- Filter synthetic imports: remove imports not referenced in entry module body ---
  // Collect identifier names from the original (non-Qwik-import) body statements.
  // We need to check which of our synthetic imports are actually used.
  let old_body_snapshot: Vec<&Statement<'a>> = program.body.iter()
      .filter(|stmt| {
          // Keep non-import statements and non-Qwik-core imports
          if let Statement::ImportDeclaration(ref decl) = stmt {
              let source = decl.source.value.as_str();
              let is_qwik = self.collected.module_imports.iter()
                  .any(|i| i.source == source && i.is_qwik_core);
              !is_qwik  // Keep non-Qwik imports in scanning
          } else {
              true
          }
      })
      .collect();
  ```

  Then collect all identifier references from these statements. A practical way: for each statement, use a recursive walk to find `IdentifierReference` nodes.

  The cleanest approach is to add a small recursive function that collects identifier names from any Statement/Expression. It doesn't need to be exhaustive -- it just needs to catch the common cases (identifier references, call expressions, member expressions, etc.):

  ```rust
  fn collect_ident_refs_from_program_body(body: &[Statement<'_>]) -> HashSet<String> {
      let mut result = HashSet::new();
      for stmt in body {
          if matches!(stmt, Statement::ImportDeclaration(_)) {
              continue;
          }
          // Convert statement to string representation and search
          // (This is a pragmatic approach since we're at exit_program
          // and the body hasn't been modified yet)
          collect_ident_refs_from_statement(stmt, &mut result);
      }
      result
  }
  ```

  **IMPORTANT:** The implementation needs to handle the fact that some identifiers appear in lazy import const declarations (`const i_XXXX = ...`) which ARE part of new_stmts, not old_body. Lazy imports should NOT be filtered -- they are always needed (they're referenced by QRL calls in the old_body). So the filtering should only apply to framework import statements, not to lazy import declarations.

  **3. Implement the filtering:**

  Split new_stmts into two groups:
  - `synthetic_imports`: The `import { X } from "@qwik.dev/core"` type statements
  - `lazy_imports_and_other`: The `const i_XXX = ...` lazy import declarations

  Filter synthetic_imports against the referenced identifiers set. Keep lazy_imports_and_other as-is.

  Here is the refined approach for `exit_program`:

  a) Build new_stmts as before (no changes to existing logic)
  b) Before body assembly, separate new_stmts into framework imports vs lazy imports
  c) Scan old_body for referenced identifiers
  d) Also scan the KEPT new_stmts for references (e.g., lazy imports reference `qrl`, so `qrl` import must be kept)
  e) Filter framework imports to only those whose local name is referenced
  f) Reassemble: filtered_framework_imports + lazy_imports + old_body

  **4. Handle non-Qwik user imports (mongodb, threejs, etc.):**

  The old_body currently preserves ALL non-Qwik imports. SWC's DCE removes unused ones. Add the same filtering for non-Qwik imports that appear in old_body:

  When iterating old_body statements, if a statement is a non-Qwik import, check if its specifiers are referenced in the REST of old_body (non-import statements). If not, skip it.

  This requires collecting references from non-import statements first, then filtering imports.

  **5. Fix entry module body ordering to match SWC:**

  SWC's ordering is:
  1. Synthetic Qrl-suffixed imports (componentQrl, useStylesQrl, etc.) - insertion order
  2. Extra top items: lazy imports (const i_XXX) + hoisted functions (_hf0, _hf0_str)
  3. Original module body: non-Qwik imports (preserved), remaining code
  4. Extra bottom items (none currently)

  OXC's current ordering is:
  1. ALL framework imports (Qrl-suffixed + tracker flags + non-dollar core)
  2. Lazy imports mixed in with framework imports
  3. Original body (non-Qwik imports in original position)

  To fix: reorder the assembly in exit_program:
  - First: Qrl-suffixed imports only (componentQrl, useStylesQrl, etc.)
  - Then: Other needed framework imports (qrl, inlinedQrl, _captures, etc.) -- but only if referenced
  - Then: Lazy import declarations (const i_XXX)
  - Then: Non-dollar Qwik core specifiers (useStore, mutable) -- but only if referenced
  - Then: Original non-Qwik body (imports + code), with unused imports filtered

  **NOTE on ordering subtlety:** SWC emits synthetic imports in insertion order (the order `ensure_core_import()` was called during traversal). For simplicity, OXC can keep the current hardcoded order which closely matches. The critical fix is the FILTERING (removing segment-only imports), not the precise ordering of kept imports.
