**const_replace.rs** -- implement `replace_build_constants()`:

The function takes `&mut Program<'a>`, `is_server: bool`, `mode: &EmitMode`, and `&'a Allocator`.

It needs to do two things:
1. **Identifier replacement**: Walk the AST and replace identifiers that are imported from `@qwik.dev/core` or `@qwik.dev/core/build`:
   - `isServer` -> `true` if is_server, else `false`
   - `isBrowser` -> `false` if is_server, else `true`
   - `isDev` -> `true` if mode is Dev, else `false`
   - Handle aliases: `import { isServer as isServer2 }` means `isServer2` should be replaced, not `isServer`

   The function needs the list of import specifiers with their local names. Either:
   (a) Accept the CollectResult which has module_imports, or
   (b) Scan program.body for ImportDeclaration nodes from `@qwik.dev/core` and `@qwik.dev/core/build` to build a HashMap<local_name, replacement_value>.

   Use approach (b) since const_replace runs after traverse and needs fresh AST info.

   Implementation: Use a simple recursive walk of the program body. For each Expression::Identifier that matches a const name in the replacement map, replace it with a BooleanLiteral. Build the replacement using `oxc::ast::AstBuilder` methods -- since we're post-traverse and don't have TraverseCtx, use OXC's standalone AstBuilder or manual AST construction.

   IMPORTANT: Since this runs after traverse_mut, we don't have TraverseCtx. Use the OXC AstBuilder directly: `let ast_builder = oxc::ast::AstBuilder::new(&allocator);` then `ast_builder.expression_boolean_literal(SPAN, value)`.

2. **Dead branch elimination**: After replacing identifiers, walk statements looking for:
   - `if (false) { ... }` -> remove entirely
   - `if (true) { ... }` -> keep only the consequent body
   - `if (false) { ... } else { ... }` -> keep only the else body
   - `if (!false) { ... }` = `if (true) { ... }` -> keep consequent
   - `if (!true) { ... }` = `if (false) { ... }` -> remove

   Also handle: `isBrowser && <expr>` -> `false && <expr>` which becomes `false` (short-circuit). The dead branch elimination must handle LogicalExpression with known boolean operands: `false && x` -> `false`, `true && x` -> `x`, `true || x` -> `true`, `false || x` -> `x`.

   For statement-level if: walk program.body and each function body recursively. When an IfStatement has a BooleanLiteral test of `false` and no alternate, remove it. When `true`, replace the IfStatement with its consequent block's statements.

   For expression-level: `false && expr` -> `false`, `true && expr` -> `expr`.

Actually, const replacement needs to happen on the main module's Program AST before emit. For segment code (which is built as strings from serialized body), the identifiers will have already been replaced in the source AST before serialization in exit_expression. So const replacement on the main Program should be sufficient.

Wait -- looking more carefully, the body code is serialized from the arrow expression DURING traverse (in exit_expression). At that point, the isServer identifiers have NOT been replaced yet (const_replace runs after traverse). So segment body code will still have raw isServer references.

The solution: Run const replacement BEFORE the traverse pass (not after). This way, when the traverse serializes body code, the identifiers are already replaced.

Actually, looking at the spec more carefully, in `example_build_server.md`, the component segment output shows:
```
export const s_ckEPmXZlub0 = ()=>{
    useMount$(()=>{
        console.log('server', mongodb());
    });
    return <Cmp>
			{<p>server</p>}
			{false}

```

The `{isServer2 && <p>server</p>}` became `{<p>server</p>}` (because isServer2=true, so `true && <p>server</p>` -> `<p>server</p>`), and `{isb && <p>server</p>}` became `{false}` (because isb=isBrowser=false, so `false && <p>server</p>` -> `false`).

And the `if (isServer)` guard was eliminated in the useTask segment, and `if (isb)` block was eliminated.

So const replacement MUST run before segment body serialization. Two options:
- (A) Run const_replace as a pre-pass on the Program AST before traverse_mut
- (B) Integrate into the traverse itself

Option (A) is simpler and cleaner. Add a call to `const_replace::replace_build_constants(&mut program, &transform_options, &allocator)` in lib.rs AFTER parsing but BEFORE creating QwikTransform and running traverse_mut.

For the collector pass: the collector needs to run BEFORE const_replace so it can identify the build constant imports. Then const_replace uses the collected import info to know which local names to replace. Then traverse_mut runs on the already-replaced AST.

Actually, const_replace doesn't need CollectResult -- it can scan ImportDeclarations directly from the Program AST. This is cleaner.
