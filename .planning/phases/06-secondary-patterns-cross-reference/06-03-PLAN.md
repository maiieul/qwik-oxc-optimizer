  <files>.planning/phases/06-secondary-patterns-cross-reference/SOURCE-MAPS-MAPPING.md</files>
  <action>
Create SOURCE-MAPS-MAPPING.md documenting the complete source map strategy and PURE annotation mechanism. The document must cover:

**1. Source Map Strategy Overview (Section 1)**
Recap the validated approach from Phase 5 POC-04:
- `oxc_codegen::Codegen::new().with_options(CodegenOptions { source_map_path: Some(path) }).with_source_text(source).build(&program)`
- Source maps generated per module (main module + each segment module)
- Key rule: Program span must encompass all preserved child spans

**2. Complete Span Strategy Table (Section 2)**
Document the span assignment for EVERY node type the optimizer constructs or moves, organized by CONV type:

**Phase 4 nodes (CONV-01, CONV-02, CONV-06):**
| Node | Span | Rationale |
|------|------|-----------|
| `qrl()` / `inlinedQrl()` call | SPAN (zero) | Constructed wrapper |
| `componentQrl` identifier | SPAN (zero) | Constructed replacement |
| Lazy import `const i_HASH = ...` | SPAN (zero) | Constructed declaration |
| Segment body (extracted arrow/function) | Preserve original | Extracted from source |
| `_captures[N]` member expression | SPAN (zero) | Constructed |

**Phase 5 nodes (CONV-05, CONV-08):**
| Node | Span | Rationale |
|------|------|-----------|
| Segment Program node | `Span::new(0, source.len())` | Must encompass children |
| Segment export declaration wrapper | SPAN (zero) | Constructed |
| Body statements inside segment | Preserve original | Moved from source |

**Phase 6 nodes (CONV-03, CONV-04, CONV-09, CONV-10, CONV-11, CONV-12, CONV-13, CONV-14):**
| Node | Span | Rationale |
|------|------|-----------|
| `_jsxSorted(...)` call | SPAN (zero) | Constructed JSX replacement |
| Props objects (varProps/constProps) | SPAN (zero) | Newly constructed objects |
| Original prop VALUE expressions | Preserve original | Extracted from JSX attributes |
| `_wrapProp(...)` call | SPAN (zero) | Constructed wrapper |
| `_fnSignal(...)` call | SPAN (zero) | Constructed wrapper |
| Hoisted function body expression | Preserve original | Extracted from prop expression |
| Hoisted function string `_hfN_str` | SPAN (zero) | Constructed |
| `_noopQrl(...)` call | SPAN (zero) | Constructed replacement |
| `_qrlSync(...)` call | SPAN (zero) | Constructed replacement |
| Stringified function arg | SPAN (zero) | Constructed |
| `isServer` -> `true`/`false` replacement | SPAN (zero) | Constructed literal |
| `_rawProps` binding | SPAN (zero) | Constructed parameter |
| `_restProps(...)` call | SPAN (zero) | Constructed |
| `_val`/`_chk` handler wrapper | SPAN (zero) | Constructed |

**Principle**: Preserve spans on AST nodes that were extracted/moved from the original source; use SPAN (zero) on nodes that are purely constructed by the optimizer.

**3. Segment Source Map Construction (Section 3)**
Document the complete pipeline for generating source maps for segment modules:
- Step 1: Collect preserved-span nodes from the original source
- Step 2: Build segment Program with `Span::new(0, source_len)` and `source_text = original_source`
- Step 3: Run codegen with `source_map_path` option
- Step 4: Extract `codegen_result.source_map` and serialize with `.to_json_string()`
- Reference Phase 5 POC-04 source_maps.rs for the validated implementation pattern

**4. Main Module Source Map (Section 4)**
Document source map generation for the main (transformed) module:
- The main module retains original Program span
- Preserved: identifiers that weren't renamed, string literals, etc.
- Newly constructed: all replacement expressions (_jsxSorted, qrl, etc.)
- Pipeline: same codegen call, original source text provided

**5. PURE Annotation Mechanism (Section 5)**
Document CONV-07 PURE comment insertion. This is the open question from Phase 4 (04-01 decision):
- **Option A (preferred)**: OXC's AstBuilder has methods like `expression_call_with_pure()` that attach PURE annotations. Check if available in oxc 0.113.
- **Option B (fallback)**: Attach a `/*#__PURE__*/` leading comment to the CallExpression node via the Program's comment list: `program.comments.push(Comment { kind: CommentKind::Block, span: Span::new(call_start, call_start), value: "#__PURE__" })`
- **Where to annotate**: All framework replacement calls: `_jsxSorted(...)`, `_jsxSplit(...)`, `componentQrl(...)`, `inlinedQrl(...)`, `qrl(...)`, `_wrapProp(...)`, `_fnSignal(...)`, `_qrlSync(...)`, `_noopQrl(...)`, `_restProps(...)`
- Frequency: CONV-07 appears in 139/162 spec files -- nearly universal

Provide Rust code for both options so implementors can choose based on OXC version.

**6. Source Map File Naming (Section 6)**
Document the output file naming for source maps:
- Main module: `{filename}.map`
- Segment modules: `{filename}_{segment_name}_{hash}.js.map`
- The `source_map_path` passed to codegen should match the output `.js` filename

**7. Import Management (Section 7)**
No new imports for source maps (handled by codegen pipeline). For PURE annotations, no imports needed (comment-based, not runtime).
