**1. Props Destructuring Transform (Section 1)**
Document the `({message, id, count: c, ...rest}) -> (_rawProps)` transformation:
- Detection: `enter_arrow_function_expression` -> check if first param is ObjectPattern AND parent is `component$()` call
- OXC API for detection: match on `ArrowFunctionExpression.params.items[0].pattern` being `BindingPatternKind::ObjectPattern`
- Parameter replacement: replace ObjectPattern with `ast.binding_pattern_identifier("_rawProps")`
- Property collection: iterate ObjectPattern properties to collect original names and local bindings
- Renamed props: `count: c` -> map local binding `c` to original name `"count"`
- Reference replacement: for each reference to a destructured binding, replace with `_wrapProp(_rawProps, "originalName")`
- Rest element: `...rest` -> `const rest = _restProps(_rawProps, ["message", "id", "count"])` inserted at function body start
- Segment metadata: `paramNames: ["_rawProps"]`

Provide a complete Rust function `transform_props_destructuring()` showing the full algorithm.

**2. _wrapProp Patterns (Section 2)**
Document both forms of _wrapProp and their OXC construction:
- Form 1 (signal): `_wrapProp(signal)` -> `ast.expression_call(wrapProp_ident, vec![signal_expr])`
  - Used when: `signalValue={signal.value}` on a component (the `.value` access is stripped, just the signal identifier is passed)
- Form 2 (named property): `_wrapProp(store, "count")` -> `ast.expression_call(wrapProp_ident, vec![source_expr, ast.expression_string_literal("count")])`
  - Used when: accessing a named property reactively on store, props, or _rawProps

Provide spec file examples for each form with line references.

**3. _fnSignal Pattern (Section 3)**
Document the computed signal expression hoisting:
- Detection: prop value contains `.value` access or store property chain inside a computed expression
- Algorithm: (a) identify all reactive sources in the expression, (b) replace each source with parameter `p0`/`p1`/..., (c) create hoisted getter function, (d) create minified string representation, (e) build `_fnSignal(_hfN, [deps], _hfN_str)` call
- Hoisted function construction: `ast.declaration_variable(VariableDeclarationKind::Const, ...)` with `ast.expression_arrow_function(params, body_expr)`
- String construction: Use `oxc_codegen::Codegen::new()` in minify mode to serialize the getter body, then wrap in string literal
- Deps array: `ast.expression_array(vec![signal_ident, store_ident, ...])`

Include the observed pattern table from 06-RESEARCH.md Section 2.3.

Reference `example_derived_signals_cmp.md` and `example_getter_generation.md` for examples.

**4. Hoisted Function Placement (Section 4)**
Document CONV-14 placement rules:
- Position: top of module, after imports, before export declarations
- Numbering: `_hf0`, `_hf1`, `_hf2`... per module (resets per segment)
- Each `_hfN` has matching `_hfN_str` string constant
- OXC API: `program.body.insert(insertion_index, hf_declaration)` for each pair

**5. Non-Wrapping Rules (Section 5)**

- Mutable wrappers -> stays as-is in varProps

- Imported dep access -> stays as-is in constProps
