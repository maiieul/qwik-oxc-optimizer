Three bugs to fix across these files:

**Bug 1 (IMPORT-01): Original $-suffixed imports not stripped from main module.**

In `transform.rs` `exit_program()`, after inserting the new imports (componentQrl, qrl, etc.) and before re-assembling program.body, add logic to strip consumed $-suffixed import specifiers from the original import declarations:

1. Walk through the existing `old_body` statements (the ones being moved from program.body).
2. For each `Statement::ImportDeclaration`, check if the import source is a Qwik core module (use `self.collected.module_imports` to check `is_qwik_core`).
3. For Qwik core imports, filter out specifiers whose local name is in `self.collected.dollar_imports`.
4. If ALL specifiers in a Qwik core import are dollar-suffixed (e.g., `import { $, component$ } from '@qwik.dev/core'`), remove the entire import declaration.
5. If SOME specifiers remain (e.g., `import { component$, useStore } from '@qwik.dev/core'` -> keep `useStore`), rebuild the import with only non-dollar specifiers. The simplest approach: skip the entire original import statement and emit a new one with just the non-dollar specifiers using `import_rewrite::build_named_import` or similar.
6. Non-Qwik imports must be preserved untouched.

Implementation approach: In the `exit_program` method, instead of blindly moving all old statements, filter them. For ImportDeclarations from Qwik core: check each specifier against `self.collected.dollar_imports`. Remove consumed specifiers. If no specifiers remain, drop the entire statement.

To rebuild imports with remaining specifiers, you can either:
- Mutate the existing ImportDeclaration by removing specifiers (complex with OXC arena types), OR
- Skip the original import and emit new individual `import { name } from "..."` statements for each remaining specifier (simpler, matches existing pattern in exit_program).

Use the simpler approach: skip the original Qwik core import entirely and add new individual imports for any non-dollar specifiers. For example, if the original was `import { $, component$, useStore } from '@qwik.dev/core'`, emit `import { useStore } from "@qwik.dev/core"` via `import_rewrite::build_named_import`.

To implement this: store which non-dollar Qwik core specifiers exist in the collected data. In exit_program, iterate `self.collected.module_imports`, find Qwik core ones, extract specifiers NOT in `self.collected.dollar_imports`, and emit new imports for them. Then when copying old_body statements, skip original Qwik core import declarations entirely.

**Bug 2 (IMPORT-02): Qrl-suffixed imports added to main module even when only segments reference them.**

Currently in `record_segment()` (transform.rs line ~423-428), ALL named $-calls get their Qrl-suffixed name added to `self.import_tracker.qrl_imports`. This means `useStylesQrl` gets added even when the `useStyles$` call is inside a component$ body (which will be extracted to a segment).

The fix: Only add a Qrl-suffixed import to the main module's `import_tracker.qrl_imports` when the $-call is at the TOP LEVEL (not nested inside another $-call). When a $-call is nested (inside another $-call body, meaning it will be extracted to a segment module), the Qrl-suffixed import should go to the segment module instead.

Detection: `self.dollar_call_stack.is_empty()` means top-level. If the stack is NOT empty, the $-call is nested and its Qrl-suffixed import should NOT be added to `import_tracker.qrl_imports`.

However, segment modules need these Qrl-suffixed imports. Currently `code_move.rs` does NOT add them. Fix: Track which Qrl-suffixed names each segment needs. Store them in `SegmentData.needed_imports` (the field already exists but is unused). Then in `code_move.rs::build_segment_code_with_hoisted()`, emit `import { useStylesQrl } from "@qwik.dev/core"` for each entry in `segment.needed_imports`.

Step-by-step for Bug 2:

1. In `transform.rs` `record_segment()`, change the Qrl-suffixed import logic (lines ~423-428): Only add to `self.import_tracker.qrl_imports` when `self.dollar_call_stack.is_empty()` (top-level). Otherwise, store the qrl_name for later association with the segment.

2. In `transform.rs` `exit_expression()` where segment capture analysis happens, after finding the matching segment in `self.segments`, if the segment has a parent (nested), add the Qrl-suffixed import name to `segment.needed_imports`.

3. In `types.rs`, confirm `SegmentData.needed_imports` is `Vec<String>` (it already is).

4. In `code_move.rs` `build_segment_code_with_hoisted()`, add a loop over `segment.needed_imports` to emit `import { name } from "core_module"` for each needed Qrl-suffixed import.

**Important edge cases:**
- Raw `$()` calls don't have a Qrl-suffixed counterpart, so no Qrl import needed.
- `sync$()` calls also don't produce Qrl imports.
- Some $-calls at top level (like `export const App = component$(() => ...)`) DO need their Qrl import in the main module -- the fix only affects NESTED calls.
- The `enter_call_expression` method also adds qrl_imports for empty-argument $-calls (line ~631-635). These should also be conditional on nesting level.
