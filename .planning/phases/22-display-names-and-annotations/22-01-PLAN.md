Two independent fixes in this task:

**Fix 1: Display names (NAME-01) -- collector.rs**

The collector's `walk_statement_for_calls` does not walk into `FunctionDeclaration` or `Declaration::FunctionDeclaration` bodies. Dollar calls inside function bodies (e.g., `export function App() { const Header = component$(...) }`) never get pre-computed `DollarCallSite` entries. The transform falls back to `s_N` naming.

Changes needed in `collector.rs`:

1. In `walk_statement_for_calls`, add a `Statement::FunctionDeclaration` arm that:
   - Saves the current `current_var_name`
   - Sets `current_var_name` to the function name (if present)
   - Walks the function body statements recursively
   - Restores `current_var_name`

2. In `collect_named_export` (the `Declaration::FunctionDeclaration` arm around line 491), after recording the export, walk the function body the same way -- save `current_var_name`, set to function name, walk body, restore.

3. In `derive_display_name`, the current logic only uses `current_var_name` directly. For nested contexts where a dollar call is inside a function that itself is inside a variable declarator, the display name needs to compose the function context. The key insight from the SWC spec output:
   - `export function App() { const Header = component$(() => ...) }` produces display name `App_Header_component`
   - The function name `App` becomes a prefix context

   The simplest approach: when entering a function body, instead of just setting `current_var_name = func_name`, compose it with any existing context. But be careful -- at top-level, `current_var_name` is `None`, so `App` alone is the context. Inside the function, when we hit `const Header = component$(...)`, the `current_var_name` becomes `Header`, and `derive_display_name` uses it with the callee suffix to get `Header_component`. The function name `App` needs to be prepended.

   Add a `scope_prefix: Option<String>` field to `CollectContext`. When entering a function body for walking, set `scope_prefix` to the function name. In `derive_display_name`, if `scope_prefix` is set, prepend it: `format!("{scope_prefix}_{rest}")`.

   Reset `scope_prefix` after walking the function body.

4. Similarly, `derive_jsx_event_display_name` should incorporate `scope_prefix` when constructing names. When `parent_display_name` is set (inside a `$()-body`), the scope_prefix is already baked into the parent. When falling back to `current_var_name`, the scope_prefix should be prepended.

**Fix 2: PURE annotations (PURE-01) -- transform.rs**

In `enter_call_expression` around line 1072-1088, the code unconditionally uses `expression_call_with_pure` for ALL `DollarCallKind::Named(name)` calls. This is wrong -- only `component$` produces a tree-shakeable wrapper.

The SWC behavior from specs:
- `componentQrl(...)` gets PURE -- tree-shakeable (component definition is side-effect-free)
- `useStylesQrl(...)`, `useTaskQrl(...)`, `useVisibleTaskQrl(...)`, `serverStuffQrl(...)`, `serverLoaderQrl(...)`, `useResourceQrl(...)` do NOT get PURE -- they are side-effectful runtime calls
- Inner `qrl()` and `inlinedQrl()` calls always get PURE (already handled correctly by `build_qrl_call` and `build_inlined_qrl_call` in import_rewrite.rs)

Add a helper function `is_tree_shakeable_dollar_call(name: &str) -> bool` that returns true only for `"component$"`. Then in the `DollarCallKind::Named(name)` branch:
- If `is_tree_shakeable_dollar_call(name)`: use `ctx.ast.expression_call_with_pure(...)`
- Otherwise: use `ctx.ast.expression_call(SPAN, qrl_callee, None::<...>, args, false)` (no PURE)

Note: Do NOT add PURE annotation logic in the `enter_jsx_opening_element` path -- JSX event handler wrappers (e.g., `Qrl(qrl(...))` for onClick$) don't get PURE either. Check `exit_expression` around line 1075-1087 where JSX event segments get their Qrl wrapper -- that also uses `expression_call_with_pure` and needs the same fix (only component$ is tree-shakeable).

After both fixes, run `cargo test` -- many snapshot files will need updating due to changed display names and PURE annotations. Update snapshots with `cargo insta review --accept` or `INSTA_UPDATE=always cargo test`.
