**reg_ctx_name handling** (transform.rs + collector.rs):

reg_ctx_name is a list of function names (e.g., ["createContext"]) that, when called, should produce a segment -- even though they don't end with `$`. The SWC optimizer treats these as "registered context" calls.

1. In collector.rs, add detection for reg_ctx_name calls:
   - During collection, check if a call expression's callee matches any name in `reg_ctx_name`
   - If so, record it as a DollarCallSite with ctx_kind = Function and ctx_name = the registered name
   - These do NOT get QRL-wrapped -- they just produce metadata segments for the build system
2. In transform.rs (or lib.rs segment building), when processing reg_ctx_name matches:
   - Generate a SegmentAnalysis with the registered name as ctx_name
   - The segment does NOT need extracted code (it's metadata-only for build coordination)
   - Or, if the SWC behavior is to extract the call body, follow that pattern
3. Check the spec files that use reg_ctx_name to understand the expected behavior:
   - Look at the spec's expected modules to determine if reg_ctx_name produces code segments or metadata-only entries

**Transpile-only edge cases** (lib.rs):

Specs with transpile_ts=true or transpile_jsx=true but no `$`-calls in the input should produce ONLY the main module (1 module total). Currently they may produce phantom segments if:
- The collector detects false-positive $-calls
- The transform creates segments for non-Qwik $ patterns

1. Verify that when no Qwik imports are present (no imports from core_module), the collector produces zero DollarCallSites
2. If the collector is producing false positives for code without Qwik imports, add a guard: skip $-call detection entirely when no Qwik imports are found in the module

After both fixes, run coverage:
