Write a diagnostic test function `test_diagnose_module_count_mismatches` that:

1. Loads all 162 specs via spec_parser::load_all_specs()
2. For each spec, runs transform_modules(build_options(spec))
3. Compares actual module count vs expected module count
4. For mismatched specs, prints a diagnostic line:
   ```
   MISMATCH {spec_name}: expected={N} actual={M} delta={M-N}
     expected_paths: [list of expected module paths]
     actual_paths: [list of actual module paths]
     config: entry_strategy={strategy}, mode={mode}, transpile_ts={bool}, transpile_jsx={bool}
   ```
5. Groups mismatches by category:
   - **too_few**: actual < expected (missing segment modules -- likely undetected $-calls or wrong strategy)
   - **too_many**: actual > expected (extra segment modules -- over-detection or wrong filtering)
6. Prints a summary at the end with counts per category

Run this test with `--nocapture` to see the full diagnostic output. Analyze the patterns:

Common failure categories to look for:
- **Aliased imports** (e.g., `component$ as Component`): collector may not detect aliased $-calls
- **Third-party modules** (e.g., `@qwik.dev/react`, `@qwik.dev/router`): custom core_module config
- **strip_exports**: specs with strip_exports config may filter modules differently
- **strip_ctx_name**: specs that strip certain ctx names
- **reg_ctx_name**: specs with registered context names may expect extra segments
- **transpile_ts/jsx only**: specs that only transpile TS/JSX without segment extraction
- **Diagnostics-only specs**: specs expecting transform errors (invalid references, etc.)
- **Multi-input specs** (relative_paths): additional inputs may produce different module structures
- **preserve_filenames**: different path naming for segments
- **explicit_extensions**: different import path extensions

After running the diagnostic test, analyze the output and identify the top 3-5 bug categories causing the most failures. Document findings as comments at the top of the test function.

  <action>
Using the diagnostic output from Task 1, fix bugs iteratively in priority order (fix the category affecting the most specs first).

**Likely fix categories based on known architecture:**

1. **Import alias detection** -- collector.rs may not handle `import { component$ as Foo } from '@qwik.dev/core'` correctly. The collector needs to track both the imported name and the local alias. When the local alias is used as a callee (e.g., `Foo(()=> ...)`), it should still be detected as a $-call.

2. **Third-party / custom core_module** -- specs with `core_module: "@qwik.dev/react"` or similar need the collector to check imports from that module, not just "@qwik.dev/core". Verify that TransformOptions.core_module is being used consistently in collector.rs.

3. **strip_exports handling** -- specs with strip_exports config (e.g., `["onGet"]`) expect certain export declarations to be removed from output. Check if filter_exports.rs is wired into the pipeline.

4. **Transpile-only mode** -- specs with transpile_ts=true, transpile_jsx=true but no $-calls should produce just 1 module (main, transpiled). Verify these aren't producing phantom segments.

5. **Invalid reference specs** -- specs like example_invalid_references, example_invalid_segment_expr1 expect diagnostics AND possibly different module structures. Verify diagnostic generation.

6. **reg_ctx_name handling** -- specs with reg_ctx_name config expect segments for registered context names. Check if this feature is implemented in transform.rs.

7. **preserve_filenames** -- affects segment output paths. Verify path construction in lib.rs respects this flag.

8. **explicit_extensions** -- affects import path extensions in lazy imports. Verify code_move.rs and lib.rs handle this.

**Iteration approach:**
- Fix one category at a time
- After each fix, run `cargo test --package qwik-optimizer-oxc test_all_specs_coverage_report -- --nocapture` to check progress
- Keep fixing until module_count_match reaches 162
- If a particular category is very complex (>30min estimated), implement the simplest correct version and move on

**Important:** Do NOT try to match exact code output. The validation target is:
- Module count matches (162/162)
- Segment metadata matches (ctxName, ctxKind, captures flag)
- Diagnostics match where specs define them
- Code is semantically correct (not byte-identical)

After all fixes, update the diagnostic test to become an assertion test:
- Rename to `test_all_specs_module_count_match`
- Assert module_count_match == specs.len()
- Keep the mismatch diagnostic output for debugging if assertion fails
