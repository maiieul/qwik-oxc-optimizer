  <name>Task 1: Build diagnostic test that categorizes all module count mismatches</name>
  <files>crates/qwik-optimizer-oxc/tests/spec_tests.rs</files>
  <action>
Add a diagnostic test function `test_diagnose_module_count_mismatches` to spec_tests.rs that:

1. Loads all 162 specs via spec_parser::load_all_specs()
2. For each spec, runs transform_modules(build_options(spec)) with source_maps=true (default)
3. Compares actual module count vs expected module count
4. For mismatched specs, prints a diagnostic line:
   ```
   MISMATCH {spec_name}: expected={N} actual={M} delta={M-N}
     expected_paths: [list of expected module paths]
     actual_paths: [list of actual module paths]
     config: entry_strategy={strategy}, mode={mode}, transpile_ts={bool}, transpile_jsx={bool}
     core_module: {core_module if not default}
     strip_exports: {strip_exports if present}
     strip_ctx_name: {strip_ctx_name if present}
     reg_ctx_name: {reg_ctx_name if present}
   ```
5. Groups mismatches by category heuristic:
   - **alias**: spec input contains `as ` pattern after a `$`-suffixed import name
   - **core_module**: spec config has non-default core_module
   - **strip_exports**: spec config has strip_exports
   - **strip_ctx_name**: spec config has strip_ctx_name
   - **reg_ctx_name**: spec config has reg_ctx_name
   - **transpile_only**: spec config has transpile_ts or transpile_jsx true but no `$` in input
   - **diagnostics_expected**: spec has expected_diagnostics
   - **other**: doesn't match above categories
6. Prints a summary with counts per category and total mismatches

The test itself should pass (it's a diagnostic -- asserts nothing, just prints). Run with `--nocapture` to see output.

After running the diagnostic, document the top failure categories as comments at the top of the function.
  </action>

<task type="auto">
  <name>Task 2: Fix import alias detection and core_module handling in collector</name>
  <files>crates/qwik-optimizer-oxc/src/collector.rs, crates/qwik-optimizer-oxc/src/transform.rs, crates/qwik-optimizer-oxc/src/lib.rs</files>
  <action>
Fix two specific bug categories based on the diagnostic output:

**Category A: Import alias detection** (collector.rs visit_import_declaration)
- Currently the collector tracks imports from `@qwik.dev/core` and checks if the imported name ends with `$`. But when a user writes `import { component$ as Foo } from '@qwik.dev/core'`, the collector must:
  1. Track the mapping: local name "Foo" -> imported name "component$"
  2. When "Foo" appears as a call expression callee, recognize it as a $-call with ctx_name "component$"
- In `CollectResult`, add a field `alias_map: HashMap<String, String>` mapping local alias -> original $-suffixed name
- In `visit_import_declaration`, when an import specifier has a different local name vs imported name AND the imported name ends with `$`, add to `alias_map`
- In QwikTransform (transform.rs), when checking if a callee is a $-call, also check `collect_result.alias_map` for the callee name. If found, use the original name as `ctx_name` and treat it as a $-call

**Category B: Custom core_module handling** (collector.rs is_qwik_import / is_qwik_symbol)
- Specs with `core_module: "@qwik.dev/react"` or `core_module: "@builder.io/qwik"` expect the collector to recognize imports from that module (not just `@qwik.dev/core`)
- Verify that the collector uses `transform_options.core_module` (passed to collect()) rather than a hardcoded `"@qwik.dev/core"` string
- If collect() does not currently receive the core_module parameter, add it. Update lib.rs to pass `transform_options.core_module` to the collector
- The collector should match imports from BOTH the configured core_module AND `@qwik.dev/core` (the configured module may re-export from core)

After fixing both categories, run the coverage report to measure improvement:
`cargo test --package qwik-optimizer-oxc test_all_specs_coverage_report -- --nocapture`

Expected: module_count_match should improve from ~78 to ~110+ (import aliases and core_module account for a significant fraction of failures).
  </action>

`cargo test --package qwik-optimizer-oxc test_all_specs_coverage_report -- --nocapture` shows module_count_match >= 100 (significant improvement from 78).
  </verify>
