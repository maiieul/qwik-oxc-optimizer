<task type="auto">
  <name>Task 1: Enable source map generation in emit_module</name>
  <files>crates/qwik-optimizer-oxc/src/emit.rs</files>
  <action>
Modify emit_module() to produce source maps when options.source_maps is true.

1. Add `source_filename: &str` parameter to emit_module() -- this is the output filename used as the `file` field in the source map JSON (e.g., "test.tsx" for main module, "test.tsx_App_component_HASH.js" for segments).

2. When `options.source_maps` is true:
   - Create `CodegenOptions { source_map_path: Some(PathBuf::from(source_filename)), ..Default::default() }`
   - Build codegen with `.with_options(options).with_source_text(source)`
   - Extract the `map` from `codegen_result.map` using `.to_json_string()` to get the JSON string
   - Return `EmitResult { code, map: Some(json_string) }`

3. When `options.source_maps` is false:
   - Keep current behavior (no source_map_path, return map: None)

Key API (from SOURCE-MAPS-MAPPING.md Section 1.1):
```rust
use std::path::PathBuf;
let codegen = oxc::codegen::Codegen::new()
    .with_options(oxc::codegen::CodegenOptions {
        source_map_path: Some(PathBuf::from(source_filename)),
        ..Default::default()
    })
    .with_source_text(source);
let result = codegen.build(program);
// result.map is Option<oxc::sourcemap::SourceMap>
// use .to_json_string() to serialize
```

Also update normalize_code() -- it does NOT need source maps (it's a formatting utility). No changes needed there.

Add 2 unit tests at the bottom of emit.rs:
- test_emit_with_source_maps: Parse a simple JS program, emit with source_maps=true, verify map is Some and contains "version":3 and "mappings"
- test_emit_without_source_maps: Emit with source_maps=false, verify map is None
  </action>

<task type="auto">
  <name>Task 2: Pipe source maps through lib.rs for main and segment modules</name>

1. In lib.rs transform_modules(), update the emit_module() call for the main module:
   - Pass `&main_path` (the output filename) as the source_filename parameter
   - The emit_result.map will now be Some(json_string) when source_maps is true
   - This already gets piped to TransformModule.map via `map: emit_result.map` -- just ensure the call signature matches

2. For segment modules (the `for seg in segments` loop):
   - For Segment/Single/Component/Smart/Hook strategy (non-inline): segments currently use string-based code construction via code_move::build_segment_code_with_hoisted() + emit::normalize_code(). Source maps for segment code require the ORIGINAL source text (not the generated segment text), because preserved spans reference original byte offsets.
   - Approach: Instead of normalize_code() (which discards source position info), emit segment code through a proper parse+codegen cycle with source map support. Modify the segment codegen path:
     a. After build_segment_code_with_hoisted() produces the raw segment JS string, parse it into a Program
     b. Run Codegen with source_map_path set to the segment output filename and with_source_text set to the ORIGINAL source (source_in_arena)
     c. However, since segment code is STRING-CONSTRUCTED (not AST-extracted with preserved spans), the segments will have zero-span nodes from re-parsing. Source maps for string-constructed segments won't map back meaningfully.
     d. PRAGMATIC DECISION: For now, generate source maps for the MAIN module (which has preserved spans and will produce useful mappings). For segment modules, set map to None since the string-construction approach loses span information. This matches the current architecture's constraint. A future refactor to AST-based segment construction would enable segment source maps.
   - Alternatively, if we want minimal segment source maps: parse the raw segment JS, emit with source_map_path but no source_text. This produces a source map with identity mappings (line N maps to line N). This is better than nothing for debugging. Use this simpler approach.

3. In code_move.rs, add a new function `emit_segment_with_map()`:
   ```rust
   pub(crate) fn emit_segment_with_map(
       raw_code: &str,
       segment_filename: &str,
       source_maps: bool,
   ) -> (String, Option<String>)
   ```
   This parses raw_code, runs Codegen with optional source_map_path, returns (normalized_code, optional_map_json).

4. In lib.rs, replace the current segment codegen path:
   - Instead of `emit::normalize_code(&raw_code)` returning just a String
   - Call `code_move::emit_segment_with_map(&raw_code, &segment_path, emit_options.source_maps)` returning (code, map)
   - Use both code and map in the TransformModule

5. Add integration test in lib.rs tests:
   - test_source_maps_present: Run transform_modules on a simple input with source_maps=true, verify main module has map: Some containing "version":3
   - test_source_maps_absent: Same with source_maps=false, verify all modules have map: None
