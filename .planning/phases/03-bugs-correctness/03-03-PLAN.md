**Part A: Fix segment ordering**

In `lib.rs`, the `for seg in segments` loop (around line 205) iterates segments in the order they were extracted during traversal. SWC's fold-based traversal produces a different order than OXC's visitor-based traverse, causing 3+ tests to have same-named segments in different order.

Fix: Sort the segments list before iterating. After `let segments = qwik_transform.extracted_segments();` add:

```rust
let mut segments = qwik_transform.extracted_segments().to_vec();
segments.sort_by(|a, b| a.display_name.cmp(&b.display_name));
```

If `extracted_segments()` returns a `&[SegmentData]`, clone/collect into a Vec first. The sort key should match whatever ordering SWC produces. Try `display_name` first (alphabetical). If that doesn't match SWC's ordering, try sorting by the original span position (`seg.span.0`) which preserves source order (SWC's fold is top-down source-order).

Actually -- SWC fold processes nodes in source order (top to bottom). OXC traverse also visits in source order. The ordering difference is likely from how segments are STORED. Check if `extracted_segments()` returns them in insertion order. If OXC uses a HashMap or similar, the order may not be deterministic. If it's a Vec, the order should match traversal order.

Investigate: Run `cargo insta test --package qwik-optimizer-oxc` and look at the 3 tests with segment ordering diffs (STATE.md mentions these). Compare segment names -- if same names, different order, then sort by span position (source order).
