**The Problem:** By the time `transform_jsx_element_inner` runs q:p injection (jsx_transform.rs lines 1495-1534), event handler lambdas have already been replaced by `enter_call_expression` with hoisted QRL identifier references. So `expr_uses_ident(value, "item")` returns false because the value is just an identifier reference to the QRL constant, not the original lambda body containing `item`.

**The Fix:** Record which iteration variables each event handler uses during `enter_call_expression` (where `body_ident_refs` is analyzed), then consume that information during q:p injection.

1. **Add side-channel field to QwikTransform** (transform.rs, near line 170):
```rust
/// Iteration variables used by event handlers in the current JSX element.
/// Populated during enter_call_expression when processing JSX event handler
/// lambdas inside loops. Drained during transform_jsx_element_inner for q:p injection.
/// Uses a Vec because multiple handlers on the same element may use different iteration vars.
pending_iter_var_usage: Vec<String>,
```
Initialize to `Vec::new()` in `QwikTransform::new()`.

2. **Populate during enter_call_expression** (transform.rs, around line 1016-1023):

The code already computes `used_iter_vars` (lines 1018-1022). After the existing param_names extension block (line 1033), add:
```rust
// Record used iteration variables for q:p injection in transform_jsx_element_inner.
// This side-channel is needed because by the time JSX transform runs,
// the handler lambdas have been replaced by QRL identifiers.
for var_name in &used_iter_vars {
    if !self.pending_iter_var_usage.contains(var_name) {
        self.pending_iter_var_usage.push(var_name.clone());
    }
}
```

3. **Thread pending_iter_var_usage to jsx_transform** (transform.rs):

In the `exit_expression` method where `transform_jsx_element_inner` is called (around line 2050-2100), before calling the function, drain the pending iter vars and pass them. Two approaches:

**Approach A (recommended):** Add a new parameter to `transform_jsx_element_inner` for pre-recorded iteration vars. Simpler approach: just pass `&self.pending_iter_var_usage` and let the function use it. Then after the call, clear `self.pending_iter_var_usage`.

However, `transform_jsx_element_inner` is a free function in jsx_transform.rs, not a method on QwikTransform. The cleanest approach is to take the pending vars before the call:
```rust
let pre_recorded_iter_vars = std::mem::take(&mut self.pending_iter_var_usage);
```
Then pass it as a parameter to `transform_jsx_element_inner`.

4. **Update `transform_jsx_element_inner` signature** (jsx_transform.rs line 1197):

Add a parameter `pre_recorded_iter_vars: &[String]` after `iteration_vars`. Update ALL call sites (search for `transform_jsx_element_inner(` in both transform.rs and jsx_transform.rs). For recursive calls within jsx_transform.rs (e.g., from transform_jsx_children processing child elements), pass `&[]` since the side-channel only applies to the top-level element being processed.

5. **Replace q:p injection logic** (jsx_transform.rs lines 1495-1534):

Replace the broken `expr_uses_ident` scanning with the pre-recorded iteration variables:

```rust
// Inject q:p / q:ps for iteration variables used by event handlers in loops
if loop_depth > 0 && !iteration_vars.is_empty() {
    // Use pre-recorded iteration variable usage from enter_call_expression.
    // The old approach (scanning expr_uses_ident on handler values) doesn't work
    // because handler lambdas are already replaced by QRL identifiers at this point.
    let used_iter_vars: Vec<String> = if !pre_recorded_iter_vars.is_empty() {
        // Filter to only vars that are actual iteration variables in scope
        pre_recorded_iter_vars.iter()
            .filter(|v| iteration_vars.contains(v))
            .cloned()
            .collect()
    } else {
        // Fallback: try the old approach for non-lambda handlers (sync$, etc.)
        let mut result = Vec::new();
        for iter_var in iteration_vars {
            let is_used = const_props.iter().any(|(key, value)| {
                key.starts_with("q-") && expr_uses_ident(value, iter_var)
            }) || var_props.iter().any(|(key, value)| {
                key.starts_with("q-") && expr_uses_ident(value, iter_var)
            });
            if is_used && !result.contains(iter_var) {
                result.push(iter_var.clone());
            }
        }
        result
    };

    if !used_iter_vars.is_empty() {
        // (existing q:p/q:ps emission code - unchanged)
    }
}
```

1. **Extend `active_props_info` to useResource$ and other hooks** (transform.rs, around line 1444):

Currently the guard is:
```rust
if name == "component$" {
    // ... analyze props destructuring
    self.active_props_info = Some(info);
}
```

The fix is to apply props analysis to ALL named `$`-suffixed calls that have arrow function arguments with destructured parameters. Change line 1444 from:
```rust
if name == "component$" {
```
To check any `$`-suffixed call:
```rust
if name.ends_with('$') && !name.starts_with("sync") {
```

BUT this is too broad -- most `$`-suffixed calls don't need props rewriting. The actual fix is narrower: SWC applies `_rawProps` rewriting to `component$` AND any call where the first param is destructured. Looking at the test diff, the issue is specifically `useResource$` where the first param `{track, cleanup}` should become `_rawProps`.

Actually, re-reading the research more carefully: the SWC behavior is that ANY `$`-suffixed call with a destructured first parameter gets `_rawProps` rewriting. This is because the segment extraction needs to capture the destructured parameter as `_rawProps` for proper serialization.

Extend the guard to include `useResource$` and other hooks that take destructured params. The safest approach: apply to any named `$`-call (not just `component$`) but ONLY the parameter rewriting part (not the body destructuring or rest_props parts which are component$-specific).

Change the `is_component_exit` check in `exit_expression` (line 2164-2170):

let is_dollar_exit =

Then in the `if let Some(ref info) = props_info` block, the `needs_transform` path (parameter rewriting + rest_props) should apply to ALL dollar calls, not just component$. The body destructuring detection (line 1462-1478 in `enter_call_expression`) should also apply to all hooks.
