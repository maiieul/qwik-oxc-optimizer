<objective>
Implement CONV-05 capture analysis: detect variables captured across $() boundaries using OXC's Scoping API, populate capture arrays in qrl()/inlinedQrl() calls, and track capture metadata on segments.

Purpose: When a $() body references variables from outer scopes, these must be serialized for Qwik's resumability. The captures are passed as the third argument to qrl()/inlinedQrl() and restored via `_captures[N]` in extracted segment bodies. This is critical for any component that uses state variables, props, or local bindings inside nested $() closures.

Output: Working capture analysis that classifies outer references into captures, import re-emissions, const inlining, and invalid captures (function/class), integrated into the transform pipeline.
</objective>

  <action>
Add a `compute_captures()` function to collector.rs that performs capture analysis for a single $() body using OXC's Scoping API. This implements the algorithm from CAPTURE-ANALYSIS-MAPPING.md.

**Core algorithm:**

```rust
pub(crate) fn compute_captures(
    scoping: &oxc::semantic::Scoping,
    body_scope_id: oxc::semantic::ScopeId,
    collect_result: &CollectResult,
) -> CaptureAnalysisResult
```

1. Iterate all symbol IDs via `scoping.symbol_ids()`
2. For each symbol, get `symbol_scope = scoping.symbol_scope_id(symbol_id)`
3. Check if the symbol is declared INSIDE the body scope using `is_scope_contained_in(scoping, symbol_scope, body_scope_id)`. If yes, skip (local variable, not a capture).
4. Check if any reference to this symbol exists INSIDE the body scope. This requires checking the reference's scope. Use `scoping.get_resolved_references(symbol_id)` to iterate all references, then for each reference determine its scope.

**Reference scope determination:**
OXC's `Scoping` does not directly expose reference scope IDs via a simple method. However, during the `traverse_mut` pass in QwikTransform, we can record a mapping of `(IdentifierReference span.start) -> ScopeId` using `ctx.current_scope_id()` in the `enter_identifier_reference` hook. Pass this mapping to `compute_captures()`.

Alternative approach (simpler, recommended): Instead of iterating all symbols globally, walk the $()-body AST recursively (similar to the existing collector walk pattern) and collect all IdentifierReference names. Then for each name, use `scoping.find_binding(body_scope_id, &name)` to check if it resolves to a symbol declared inside the body. If not found inside the body, use `scoping.find_binding(parent_of_body_scope, &name)` walking up -- or simpler: check if the name resolves to a symbol in any ancestor scope of the body. If the resolved symbol's scope is NOT the body or a descendant, it is a capture candidate.

**Simplest practical approach:** During the Traverse pass, when we are inside a $()-body (tracked via the dollar_call_stack), record each IdentifierReference name and the scope where it was referenced. After exiting the $()-body, compare against the body scope to find outer references.

Actually, the most pragmatic approach for Phase 9 is:
- In `enter_call_expression` when detecting a $() call, record the current scope ID as `body_parent_scope`
- The body's function scope is one level deeper
- After the call is processed (exit_expression), use the Scoping API to check which identifiers referenced in the body resolve to symbols declared outside the body scope

**Implementation using Scoping directly:**

Since `Scoping` has `scope_ancestors()` and `find_binding()`, we can:

1. Get the body_scope_id from `ctx.current_scope_id()` when entering the arrow function body inside a $() call
2. For capture analysis, walk the arrow function body AST (recursively, same pattern as existing collector) and collect all `IdentifierReference` names
3. For each collected name:
   a. Use `scoping.find_binding(body_scope_id, &name)` -- if found, it's declared inside the body, skip
   b. Walk up using parent scopes: use `scoping.scope_parent_id(body_scope_id)` then `scoping.find_binding(parent_scope, &name)`
   c. Actually simpler: collect the name, then check `scoping.get_binding(body_scope_id, &name)` for each scope from body upward. If the binding is in a scope that is body or descendant of body, it's local. If in an ancestor of body, it's a capture candidate.

**Even simpler practical approach:**
Just collect all identifier reference names from the body AST (using a recursive walk), then for each:
- Check if it's declared inside the body scope tree using `scoping.find_binding(body_scope_id, &name)` -- this walks UP the scope tree. If the result's scope is an ancestor of body_scope_id but NOT body_scope_id or its descendants, it's an outer reference.

**Actually, the most robust approach:**
Use the fact that the Scoping already has all bindings resolved. We need:
1. The ScopeId of the $()-body function
2. For each `SymbolId` in the program, check if (a) it's declared outside body scope and (b) has references inside body scope

For (b), we need to know which scope each reference is in. The key insight: `scoping.get_resolved_references(symbol_id)` returns `ReferenceId`s. In OXC 0.113, we can try `scoping.reference_scope_id(ref_id)` if available, or use `scoping.reference_node_id(ref_id)` to look up the scope.

**Practical decision:** Because OXC API specifics may vary, take a hybrid approach:
- During Traverse, in `enter_identifier_reference`, if we're inside a $()-body (tracked by dollar_call_stack depth), record the identifier name into a `body_ident_refs: Vec<String>` on QwikTransform.
- After exiting the $()-body in `exit_expression`, pass the collected names to `compute_captures()`.
- `compute_captures()` then classifies each name by looking it up in the collector's import data and checking symbol flags.

```rust
pub(crate) struct CaptureAnalysisResult {
    pub capture_names: Vec<String>,
    pub reemitted_imports: Vec<(String, String, bool)>,  // (local, source, is_default)
    pub inlined_consts: Vec<String>,
    pub diagnostics: Vec<String>,
}
```

For each identifier name collected from the body:
- If name is declared inside body (local var/param of the body function or inner functions), skip
- If name is a global (console, undefined, etc.) with no binding, skip
- If name is in `collect_result.module_imports` with `is_qwik_core: true` or any import, classify as ImportReemit
- If name matches a const declaration with a literal initializer (check via scoping.symbol_flags for ConstVariable + AST inspection), classify as ConstInline
- If name matches a function or class declaration (SymbolFlags::Function/Class), classify as InvalidCapture
- Otherwise: LocalCapture, add to capture_names

**Simplified capture classification (practical for Phase 9):**
Since full Scoping API access during Traverse is complex (traverse_mut takes the Scoping), use a simplified approach:

1. During Traverse, collect all IdentifierReference names from the $()-body
2. In exit_expression, determine captures using available data:
   - **Import check:** If name appears in `collect_result.module_imports.specifiers`, it's an import -- classify as ImportReemit
   - **Body-local check:** If name is a parameter of the $()-body arrow function, or declared in a let/const/var inside the body, it's local -- skip
   - **Dollar import check:** If name is in `collect_result.dollar_imports`, it's a framework import -- skip (already handled by QRL rewriting)
   - **Global check:** Skip known globals (console, undefined, window, document, etc.)
   - **Otherwise:** It's a capture candidate (LocalCapture)

For const literal inlining, this can be deferred to Phase 10 (code_move) where the segment body is actually constructed. For Phase 9, focus on correctly identifying which names are captured (the critical path) and recording them on SegmentData.

3. **Body-local detection:** When entering the arrow function body of a $() call, start a new scope tracking. Track declarations seen inside the body:
   - Add `body_local_decls: HashSet<String>` field to QwikTransform
   - In `enter_variable_declarator` (add new Traverse hook), if inside a $()-body, record the declarator's binding name
   - In `enter_formal_parameter` or at the start of processing, record the arrow function's parameter names
   - These names are body-local and should NOT be captures
