  <name>Task 1: Implement POC-03 (multi-module output)</name>
  <files>poc/src/poc_03_multi_module.rs</files>
  <action>
Implement POC-03 based on MULTI-MODULE-OUTPUT-MAPPING.md (created in plan 05-01) and 05-RESEARCH.md Pattern 2.

The program should demonstrate splitting one input Program into a main module + one or more segment modules, producing valid JavaScript output for both.

**Approach: Simplified demonstration of the split pattern.**

Rather than implementing the full optimizer transform (which is v3.0 work), demonstrate the AstBuilder construction capability:

1. Parse a test input (use example_1.md source code which has `export const renderHeader = $(() => { ... })`)

2. Generate the main module output by running codegen on the parsed program (as-is for this POC -- the full transform that replaces $() with qrl() is v3.0 work)

3. Construct a segment Program from scratch using AstBuilder:
   - Build an import declaration: `import { qrl } from "@qwik.dev/core"` (framework import)
   - Build an exported const with an arrow function body: `export const renderHeader_hash = () => { return ... }`
   - Assemble into a complete Program via `ast.program(SPAN, SourceType::mjs(), None, ast.vec(), body)`

4. Run codegen on both Programs:
   - Main: `Codegen::new().with_source_text(source).build(&main_program)`
   - Segment: `Codegen::new().build(&segment_program)`

5. Print both outputs to stdout, showing that:
   - Main module produces valid JavaScript
   - Segment module produces valid JavaScript with the export declaration
   - Both outputs are generated from Programs sharing the same Allocator

6. Also demonstrate the hash computation:
   - Implement `compute_segment_hash(scope, rel_path, display_name) -> String` from the research
   - Uses DefaultHasher, base64url encoding, '-'/'_' -> '0' replacement
   - Compute the hash for "renderHeader" from "test.tsx" and print it
   - Compare against the known hash from example_1.md spec (renderHeader_zBbHWn4e8Cg -- verify this from the spec file)

**Key AstBuilder APIs to exercise:**
- `AstBuilder::new(allocator)` for creating the builder
- `ast.vec()` and `ast.vec1()` for arena-allocated vectors
- `ast.atom()` for interned strings
- `ast.binding_pattern_kind_binding_identifier()` for binding patterns
- `ast.variable_declaration()` + `ast.variable_declarator()` for const declarations
- `ast.expression_arrow_function()` for arrow function expressions
- `ast.module_declaration_export_named_declaration()` for export statements
- `ast.import_declaration()` for import statements (if this method exists; otherwise construct ImportDeclaration manually)
- `ast.program()` for the final Program node

NOTE: The AstBuilder API may differ from research. Some methods may not exist or may have different signatures. If `ast.program()` doesn't exist, construct Program directly via struct initialization: `Program { span: SPAN, source_type: SourceType::mjs(), ... }`. If import construction is complex, simplify to just the export declaration. The goal is a WORKING program that demonstrates multi-module construction, even if simplified.

Run `cargo build --manifest-path poc/Cargo.toml --bin poc-03-multi-module` and `cargo run --manifest-path poc/Cargo.toml --bin poc-03-multi-module`.

<task type="auto">
  <name>Task 2: Implement POC-04 (source maps for split modules)</name>
  <files>poc/src/poc_04_source_maps.rs</files>
  <action>
Implement POC-04 based on 05-RESEARCH.md Pattern 3 (source map generation) and the codegen pipeline from MULTI-MODULE-OUTPUT-MAPPING.md.

The program should demonstrate source map generation for both main and segment modules produced from the same input source.

1. Parse a test input (use example_1.md source code)

2. Generate main module with source map:
   ```rust
   let options = CodegenOptions {
       source_map_path: Some(PathBuf::from("test.js")),
       ..CodegenOptions::default()
   };
   let result = Codegen::new()
       .with_options(options)
       .with_source_text(source)
       .build(&main_program);
   ```

3. Construct a segment Program using AstBuilder (reuse the construction pattern from POC-03):
   - Build a simple segment with an exported arrow function
   - For nodes extracted from the original source, PRESERVE their spans (use non-zero Span values from the original AST)
   - For newly constructed nodes (import declarations, export wrapper), use `SPAN` (zero span)

4. Generate segment module with source map:
   ```rust
   let seg_options = CodegenOptions {
       source_map_path: Some(PathBuf::from("test_renderHeader_hash.js")),
       ..CodegenOptions::default()
   };
   let seg_result = Codegen::new()
       .with_options(seg_options)
       .with_source_text(source)  // original source for mapping
       .build(&segment_program);
   ```

5. Print for each module:
   - The generated JavaScript code
   - Whether a source map was generated (result.map.is_some())
   - The source map JSON string (via `map.to_json_string()`)
   - Basic source map validation: check that the JSON parses, contains "mappings" field, and has "sources" array

6. Demonstrate span preservation:
   - Show that nodes with original spans produce source map entries (non-empty mappings)
   - Show that nodes with SPAN (zero) produce no source map entries for those positions
   - Print a summary: "Main module: N source map entries", "Segment module: M source map entries"

**Key APIs to exercise:**
- `CodegenOptions { source_map_path: Some(PathBuf::from(...)), .. }` for enabling source maps
- `Codegen::new().with_options(options).with_source_text(source).build(program)` for codegen
- `CodegenReturn { code: String, map: Option<SourceMap> }` for accessing results
- `source_map.to_json_string()` for JSON serialization

NOTE: If `to_json_string()` doesn't exist on SourceMap, try `to_json()` which may return a struct, or use serde serialization. If source map output differs from expectations, document what actually happens. The goal is demonstrating that OXC codegen CAN produce source maps for constructed Programs.

Run `cargo build --manifest-path poc/Cargo.toml --bin poc-04-source-maps` and `cargo run --manifest-path poc/Cargo.toml --bin poc-04-source-maps`.
