   - IdentCollector -> Iterate `IdentifierReference` nodes in body, check `scoping.has_binding(ref_id)` for resolution

2. **Allocator Strategy** -- Document the shared allocator approach (recommended for POC) vs separate allocators:
   - Shared: Single Allocator for main + all segments. All Programs share lifetime 'a. Must codegen ALL before dropping allocator.
   - Separate: One Allocator per segment. Each Program has independent lifetime. Can codegen independently. Enables parallel codegen via rayon later.
   - Recommendation: Shared allocator for POC simplicity, with a note that the production optimizer may switch to separate allocators per the ARCHITECTURE-BLUEPRINT.md data flow specification.

3. **Segment Program Structure** -- What a segment module contains:
   - Import declarations (re-emitted imports from capture analysis, framework imports like _captures)
   - Lazy import declarations (for nested $-calls: `const lazyHash = () => import("./path")`)
   - Exported const declaration containing the segment body as an arrow function
   - Document the exact structure with code examples matching spec file output patterns

4. **AstBuilder Construction API** -- Complete Rust code for building each segment component:
   - `build_named_import(name, source, ast)` -- Construct `import { name } from "source"`
   - `build_lazy_import_declaration(hash, path, ast)` -- Construct `const hash = () => import("path")`
   - `build_segment_export(name, body_expr, ast)` -- Construct `export const name = (params) => { body }`
   - `build_segment_program(allocator, segment_data)` -- Assemble the complete Program

   Use AstBuilder methods: `ast.vec()`, `ast.vec1()`, `ast.atom()`, `ast.binding_pattern()`, `ast.variable_declaration()`, `ast.program()`, `ast.import_declaration()`, `ast.expression_arrow_function()`, `ast.module_declaration_export_named_declaration()`.
