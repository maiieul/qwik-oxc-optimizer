  <name>Task 2: Implement POC-02 (capture analysis using oxc_semantic)</name>
  <files>poc/src/poc_02_capture_analysis.rs</files>
  <action>
Implement POC-02 based on the capture analysis algorithm from CAPTURE-ANALYSIS-MAPPING.md (created in plan 05-01) and the POC-02 code example in 05-RESEARCH.md.

The program should:

1. Define test inputs from spec files with KNOWN capture results:
   - example_multi_capture.md: Foo component has a nested $() that captures _rawProps (after props destructuring) and inlines arg0=20 as a const literal. Bar component has a nested $() that captures _rawProps.
   - example_inlined_entry_strategy.md: has useBrowserVisibleTask$() that captures `state` (from useStore)
   - example_capture_imports.md: has useStyles$() with CSS imports that should be RE-EMITTED, not captured

2. Implement the capture analysis algorithm:
   - Parse input code
   - Build Scoping via SemanticBuilder
   - Implement `compute_captures(scoping, body_scope_id) -> Vec<CaptureInfo>` following the algorithm in CAPTURE-ANALYSIS-MAPPING.md
   - CaptureInfo should contain: name (String), is_import (bool), is_const_literal (bool)
   - Use `is_scope_contained_in(scoping, inner, outer) -> bool` helper using `scope_ancestors()`

3. For the capture classification:
   - Check `symbol_flags` for SymbolFlags::Import -- these are re-emitted imports, not captures
   - Check if the symbol's binding is a const with a literal initializer -- these are inlined, not captures
   - Everything else that's an outer-scope local variable is a genuine capture

4. The key challenge: identifying the body_scope_id for each $() call. During traversal, when entering a call expression that's a $() call, the first argument (arrow function) creates a new scope. That scope's ID is the body_scope_id. Use the Traverse API to track this -- you may need to:
   - In `enter_call_expression`, detect $() and mark that the next arrow/function expression is a dollar body
   - In `enter_arrow_function_expression` (or similar), record the current scope_id via `ctx.current_scope_id()`
   - After traversal completes, use the recorded scope IDs to run capture analysis

   If `ctx.current_scope_id()` is not available inside Traverse hooks, use an alternative approach: after building Scoping, walk the AST manually to find the arrow function's scope by examining child scopes of the call expression's scope.

5. Print results for each test case:
   - Which variables are captured (local variables referenced from outer scope)
   - Which are imports (should be re-emitted)
   - Which are const literals (should be inlined)
   - Compare against known results from spec files

NOTE: The exact OXC API may differ from research. If `symbol_flags` doesn't have an `Import` variant, look for alternative ways to check if a symbol is an import binding (e.g., check if the symbol's declaration is an ImportDeclaration). If `get_resolved_references` doesn't return what's expected, try alternative approaches. The goal is WORKING CODE that correctly identifies captures, even if the implementation differs from the research pseudocode.

Run `cargo build --manifest-path poc/Cargo.toml --bin poc-02-capture-analysis` and then `cargo run --manifest-path poc/Cargo.toml --bin poc-02-capture-analysis` to verify output.
