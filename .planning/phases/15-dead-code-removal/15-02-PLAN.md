  <name>Task 1: Consolidate collector.rs near-duplicate functions (DEAD-03)</name>
  <files>crates/qwik-optimizer-oxc/src/collector.rs</files>
  <action>
    collector.rs currently has three functions that extract binding names from AST declarations:

    1. `collect_declaration_names(names, decl: &Declaration)` (line 283) -- handles VariableDeclaration, FunctionDeclaration, ClassDeclaration
    2. `collect_statement_decl_names(names, stmt: &Statement)` (line 336) -- handles VariableDeclaration (as Statement variant), FunctionDeclaration, ClassDeclaration
    3. `collect_binding_pattern_names_into(names, pattern: &BindingPattern)` (line 306) -- recursive pattern walker shared by both

    Functions 1 and 2 are near-duplicates: `collect_statement_decl_names` matches on Statement variants that contain the same declaration types, then does the exact same extraction as `collect_declaration_names`. The difference is only the wrapper type (Declaration vs Statement).

    **Consolidation approach:**
    1. Keep `collect_declaration_names` as the canonical function -- it handles `Declaration` directly
    2. Keep `collect_binding_pattern_names_into` as the recursive helper (unchanged)
    3. Rewrite `collect_statement_decl_names` to delegate to `collect_declaration_names`:

    ```rust
    fn collect_statement_decl_names(names: &mut HashSet<String>, stmt: &Statement<'_>) {
        if let Some(decl) = stmt.as_declaration() {
            collect_declaration_names(names, decl);
        }
    }
    ```

    This is the correct consolidation because:
    - Statement variants `VariableDeclaration`, `FunctionDeclaration`, `ClassDeclaration` ARE Declaration variants accessed through the Statement enum
    - OXC's Statement type has an `as_declaration()` method that returns `Option<&Declaration>` for these variants
    - The fallthrough `_ => {}` in both functions means non-declaration statements and non-relevant declarations are already ignored

    **If `as_declaration()` is not available on Statement:** Instead use a match:
    ```rust
    fn collect_statement_decl_names(names: &mut HashSet<String>, stmt: &Statement<'_>) {
        match stmt {
            Statement::VariableDeclaration(_)
            | Statement::FunctionDeclaration(_)
            | Statement::ClassDeclaration(_) => {
                // These Statement variants are also Declaration variants.
                // Extract the Declaration and delegate.
            }
            _ => {}
        }
        // If direct delegation isn't possible, keep the current 3-arm match
        // but call collect_declaration_names logic through a shared path.
    }
    ```

    The simplest correct approach if `as_declaration()` doesn't exist: inline `collect_statement_decl_names` at its single call site (line 399) by matching Statement variants there and calling `collect_declaration_names` for the declaration-carrying variants. Then delete `collect_statement_decl_names` entirely.

    At the call site (line 399), change:
    ```rust
    // Before:
    collect_statement_decl_names(&mut ctx.module_level_decls, stmt);

    // After:
    match stmt {
        Statement::VariableDeclaration(var_decl) => {
            collect_declaration_names(
                &mut ctx.module_level_decls,
                &Declaration::VariableDeclaration(var_decl.clone()),
            );
        }
        _ => {
            // FunctionDeclaration and ClassDeclaration are already handled
            // by the ExportNamedDeclaration branch above.
            // Non-exported top-level function/class declarations go through
            // here but are rare and not critical for module_level_decls.
        }
    }
    ```

    Actually, the simplest approach: since Statement::VariableDeclaration, Statement::FunctionDeclaration, and Statement::ClassDeclaration ARE the exact same inner types as Declaration::VariableDeclaration etc., just keep `collect_statement_decl_names` but have it extract and delegate. The key insight is that both functions call `collect_binding_pattern_names_into` for var decls and `names.insert(ident.name...)` for fn/class decls -- identical logic.

    **Preferred final approach:** Delete `collect_statement_decl_names` and inline its logic at the call site (line 399 in the `collect` function), using `collect_binding_pattern_names_into` directly for VariableDeclaration and direct `names.insert` for FunctionDeclaration/ClassDeclaration. This removes the near-duplicate without introducing new complexity.

    The remaining warnings are about struct fields that are populated by the collector/transform but only read in test code. These are intentional data-model fields (not dead code), so the correct fix is targeted `#[allow(dead_code)]` on each affected struct -- NOT file-level blanket attributes.

    Add `#[allow(dead_code)]` to these structs in types.rs:

    1. **DollarCallSite** (line ~443): Fields `callee_name`, `is_nested`, `parent_name` are populated by collector.rs and read in collector tests. `display_name` and `span` ARE read in production code (transform.rs, lib.rs). Add `#[allow(dead_code)]` to the struct.

    2. **ImportInfo** (line ~463): Field `span` is populated but never read in production code (used in tests). `source`, `specifiers`, `is_qwik_core` ARE read. Add `#[allow(dead_code)]` to the struct.

    3. **ExportInfo** (line ~479): Fields `name`, `is_reexport`, `span` are populated but only read in collector tests. Add `#[allow(dead_code)]` to the struct.

    4. **SegmentData** (line ~493): Fields `origin`, `needed_imports`, `body_span`, `body_code` are populated but not read in production code. Other fields like `display_name`, `hash`, `name`, `ctx_name`, `ctx_kind`, `captures`, `capture_names`, etc. ARE read. Add `#[allow(dead_code)]` to the struct.

    5. **TransformOptions** (line ~555): Multiple fields populated from user config but not all read by every code path. Add `#[allow(dead_code)]` to the struct.

    6. **CollectResult** (line ~420): Field `module_exports` populated but not read in production code. Add `#[allow(dead_code)]` to the struct.

    7. **CaptureAnalysisResult** in collector.rs (line ~27): Fields `reemitted_imports` and `diagnostics` are populated but only read in tests. Add `#[allow(dead_code)]` to this struct in collector.rs.

    For each struct, place `#[allow(dead_code)]` on the line immediately before the struct definition, after any doc comments and derive macros. Example:

    ```rust

    #[derive(Debug, Clone)]
    #[allow(dead_code)]
    pub(crate) struct DollarCallSite {
    ```

    This approach:
    - Does NOT use file-level `#![allow(unused)]` (which the requirements prohibit)
    - Documents that these fields are intentionally part of the data model
    - Suppresses only the specific struct warnings, not unrelated issues
    - Preserves field names for test readability and future use
